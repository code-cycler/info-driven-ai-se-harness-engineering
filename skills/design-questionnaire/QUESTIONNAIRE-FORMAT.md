# 问卷格式规范(design-questionnaire 引擎 · 复用件)

> 本文件与 [PROCESSING-RULES.md](./PROCESSING-RULES.md) 共同构成问卷引擎。后续 skill(如 retro-questionnaire)复用这两个文件,只换自己的骨架模板。

## 文件约定

- 活动问卷目录:`harness/questionnaires/`(懒创建,首次生成问卷时才建)
- 命名:
  - init 模式:`<stage>-w<NN>.md`(stage ∈ `vision` | `hld` | `lld`;NN 从 00 递增,**w00 = preview 独立波**,w01 起为正式题波)
  - feature 模式:`feature-<slug>-<stage>-w<NN>.md`(slug 为功能短名,kebab-case;w00 同理为 preview)
  - 同 wave 超题量拆子波:`<stage>-w<NN>a.md`、`<stage>-w<NN>b.md`
- 归档:处理完毕移入 `harness/questionnaires/archive/`,文件名不变,只移不删

## frontmatter(必填)

```yaml
---
mode: init | feature
wave: 0             # 0 = preview 独立波;1+ = 正式题波
stage: vision | hld | lld
created: YYYY-MM-DD
status: pending | answered | processed | archived
---
```

status 流转:`pending`(已生成待作答)→ `answered`(用户答完待解析)→ `processed`(已落盘待归档)→ `archived`(已归档)。

## 文件结构

每阶段 = **W00(preview,独立问卷)+ W01+(正式题波)** 两类文件,**分开交付**(不与 W01 同出)。

### W00 · preview 问卷模板(`<stage>-w00.md`)

```markdown
---
mode: init
wave: 0
stage: vision | hld | lld
created: YYYY-MM-DD
status: pending
---

# 问卷 <stage> W00 · Preview(决策默认值 yes/no 速答)

> **本波是 preview 预答层**(独立 wave 0):把 AI 有明确默认倾向的决策点逐条列出,人只做 yes/no 速答。
>
> **作答规则**:
> - **预勾选 = opt-in 开关**(2026-08-03 起,默认关):仅当你启动本 skill 时明确说「预勾选」,要点才预勾 `[x]`(勾 = 采纳默认);未启用时全部 `[ ]`,人逐条作答
> - **取消勾选(留空)= 不采纳** → 该要点转入 W01 单独拷问(出选项深究)
> - **单向门要点(发布 / 删除 / 花钱 / 脱敏等不可逆)永不预勾**,强制人逐条显式勾选确认
> - 本波**不用 🤔**(yes/no 二选一,无中间态);真定不了 → 取消勾选即可,转 W01 深究
> - 若"大体同意但要改一两处" → 取消勾选,转 W01 时在深究题里给自定义值
>
> 默认来源标注于〔〕。预勾开关自 2026-08-03(OD-14 修订):opt-in 默认关,排序保留默认;单向门豁免 + 预勾设防为开关开启时的双保险。

## 决策默认值清单

- [ ] **1 <决策点>**:<AI 默认倾向> 〔来源〕(opt-in 开关开启时预勾 `[x]`;单向门要点永不预勾,标注「单向门,须显式勾选」)
- [ ] **2 <决策点>**:<AI 默认倾向> 〔来源〕
……

## 补充声明

<任何想补充的话……没有就留空。agent 处理时必读>
```

### W01+ · 正式题问卷模板(`<stage>-w01.md` 起)

```markdown
---
mode: init | feature
wave: 1
stage: vision | hld | lld
created: YYYY-MM-DD
status: pending
---

# 问卷 <stage> W<NN> · <一句话主题>

> **与 W00 的关系**:W00(preview yes/no)中**留空(不采纳)**的要点,处理后会作为正式题**追加到本波尾部**逐个深究。本波另列**开放型骨架必答项**(多选/方向型,不适合 W00 的 yes/no)。

> **填写规则**:
> 1. 每题勾选 `[x]`;默认单选,标「(多选)」可勾多个,选项数不限
> 2. ★ = 推荐选项,附推荐理由;**预勾选 = opt-in 开关**(默认关:你明确说「预勾选」才预勾;见规则 15);**单向门题永不预勾**(见规则 16)
> 3. 每题末尾 🤔 是逃生舱:勾了 = 我定不了 → agent 走降风险协议,绝不重问
> 4. 选项都不合适 → 在 ✍️ 自定义 后自由书写
> 5. 标「条件:Qn 选 X 才答」的是内联浅分支,条件不满足直接跳过
> 6. 选项排序 = 非推荐在前 → 逃生舱倒数第二 → 推荐最后(规则 14)

## Q1. <问题文本>   [落盘: <目标文档#章节>]

<可选:出题依据——探索发现的事实/矛盾/盲点,一两行,附出处>

- [ ] A. <选项>  —— <代价/风险>
- [ ] B. <选项>  —— <定位/利弊>
- [ ] 🤔 我定不了 → 推迟/降风险
- [ ] C. <选项>  ★推荐 —— <理由>(opt-in 开关开启时预勾;单向门题永不预勾)
- ✍️ 自定义: __________

### Q1.1 (条件: Q1 选 B 才答) <浅分支子问题>   [落盘: <目标文档#章节>]

- [ ] ……
- [ ] 🤔 我定不了 → 推迟/降风险
- ✍️ 自定义: __________

---

## W00 处理后追加区(W01 必有占位)

> W00 中留空(不采纳)的要点,处理报告产出后在此处追加为正式题,逐个出选项深究。

---

## 补充声明

<任何想补充的话:新需求、格式反馈、范围调整、临时想到的风险……没有就留空。agent 处理时必读>
```

## 规则细则

1. **选项数不限**,但每个选项必须带一句定位、利弊或代价,不能只给名词。
2. **★推荐**:agent 有明确倾向时标一个(只能标一个),必须附理由;没有倾向就不标,不硬凑。
3. **🤔 逃生舱**:**W01+ 正式题每题必有**,固定在选项末尾、✍️自定义之前。**W00 preview 不用 🤔**(yes/no 二选一,无中间态)。对话速答中出现「不知道/不确定/你决定/推迟/看你」等,视同勾了逃生舱。
4. **✍️自定义**:W01+ 每题必有。对话速答的自定义内容逐字转写到该行,不润色、不概括。
5. **内联浅分支限 1 层**(允许 `Qn.m`,禁止 `Qn.m.k`);更深的分支不在本问卷展开,记入处理报告的「下一波候选」。
6. **[落盘:] 提示**:W01+ 每题必标,取值见 PROCESSING-RULES.md 的落盘映射表。出题时标错,处理时可纠正,但必须在处理报告中说明。
7. **出题依据**:凡因探索发现(代码矛盾、术语冲突、上轮答案引出)而出的题,必须在题干下注明依据和出处,让用户能判断这题为什么存在。
8. **题量**:正式题波每波上限 10 题(2026-08-08 用户裁决收紧,原 10–15);阶段骨架未覆盖项优先于动态盲点;超量拆子波。**W00 preview 不受此限**(要点数建议 10–25)。
9. **多选标记**:默认单选;确实可同时成立多个答案的题,在题干尾部标「(多选)」。
10. **Markdown 排版**:数值范围用 en dash(`–`),禁止半角 `~` 表示范围;遵循全局排版规范。
11. **安全**:问卷中禁止出现密钥、真实隐私数据、未公开商业机密(方法论 §8.8);涉及安全关键设计的题,在出题依据中标注「需人逐行审查」。
12. **补充声明区**:W00 与 W01+ 末尾均固定设「补充声明」自由书写区。agent 处理问卷时必读,内容按类型处理:新需求 → 下一波或修订规格;答案补遗 → 按映射落盘;格式反馈 → 修订本规范。所有去向写入处理报告。
13. **preview(每阶段独立 W00)**:每阶段先生成独立 `<stage>-w00.md`(preview 问卷),**不与 W01 同文件**。一要点一行 = 决策点 + AI 默认倾向 + 来源,要点数建议 10–25,须覆盖本阶段骨架必答项中 AI 有明确倾向者。每条**预勾与否由 opt-in 开关决定**(2026-08-03 起,默认关:用户启动本 skill 时明确说「预勾选」才预勾 `[x]`,勾 = 采纳默认按默认落盘;未启用时全部 `[ ]`,人逐条作答);**单向门要点永不预勾**,强制人显式勾选;**取消勾选(留空)= 不采纳**(转入 W01 深究)。**W00 不用 🤔**(yes/no 二选一);底部补充声明栏保留。W01 正式题 = W00 取消勾选(不采纳)要点的深究 + 不适合 yes/no 的开放型骨架必答项;已在 W00 勾选采纳的必答项不重复出题,处理报告标注来源 = W00 预答。
14. **选项级排序(默认行为,2026-08-03 起)**:每题选项顺序 = **非推荐选项在前 → 🤔 逃生舱倒数第二 → ★推荐选项最后**(利用线性阅读,推荐项是用户扫到最后才看到的「答案」)。★推荐仍只标一个、附理由;排序不依赖预勾开关。
15. **问题级排序(OD-14 试点,2026-08-01 起)**:「缺少信息 / 无法实测」的题放整份问卷**最前**——最早暴露信息缺口,用户在精力最好时处理。「无法实测」判据(用户定义):① agent 能力(工具 / 脚本 / bash 命令)实测无结果;② 实测后无有效结论。判据成立与否在**出题时**判定并标注(不靠运行时分类);题放最前的同时,出题依据须注明「未实测 / 无结论」与已尝试的实测手段。
16. **单向门题豁免**:涉及**发布 / 删除 / 花钱 / 脱敏**等不可逆后果的题,**永不预勾**(opt-in 开关开启与否都不预勾),强制人逐条显式作答;处理时逐条复核非默认状态(设防见 PROCESSING-RULES.md「预勾设防」)。
