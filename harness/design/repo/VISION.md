## 目标与受众 (V1)

**核心目标**:同时优化本仓库的**哲学与方法论内容**和**具体架构**——

- **内容修订(升 v4)**:方法论文件 + 哲学文件升 v4(canonical,OD-4 流程),实操文件随同步走轻量流程。修订内容:
  1. **受众彻底收窄为个人开发者**(W01 Q2 选 A:适用对象只写个人,团队场景删除或仅一句带过);**收窄影响 §零 与叙事,机制内容保留重述为「个人 × AI 代理」视角**(压测 Q6——delegate/分工对个人同样有效,受众是读者画像不是内容过滤器);
  2. **第二支柱立论层对称化**(W01 Q3 选 A:照第一支柱模式补机制层立论,两支柱完全对称——纪律为何在 AI 场景失效 / 为何 AI 让纪律更便宜);**对称 = 只补机制层立论(护栏机制显性化),不建度量/症状层**(压测 Q5——第一支柱三层是因果链,第二支柱强建度量/症状层牵强);
  3. **术语折中审计 + 新词门槛**(W01 Q4 选 C + 自定义:本次保留核心词/合并重叠/学科替换,新词引入过闸门;长期全面审计进 TODO);**含 ADR-0005 四处一致核心子串同步修订**(压测 Q2——术语替换击穿标准措辞与 DoD grep,必须一并更新);
  4. **哲学文件按学科视角重构**(W01 Q5 选 C:人因工程 / 软件工程 / 运筹学三学科为骨架)。
- **架构优化**:文档体系 + 规则优先级 + 入口布局(W01 Q9 选 C 维持默认范围;AGENTS.md 作入口路由不复制规则)。

**受众**:设计产物服务维护者本人 + AI 代理(Claude Code / Codex)+ 未来贡献者(OD-3);方法论文章读者(收窄后的个人开发者)。

## 范围 (V2)

### 做什么

1. 方法论文件 + 哲学文件升 v4,内容修订(受众 / 第二支柱 / 术语 / 学科重构)
2. 实操文件同步修订(轻量流程)**——术语联动处(若有)并入 P3 处理,不预设受众步**(压测 Q9:grep 实证实操文件无受众表述,P4 空转风险)
3. 术语审计(折中档)+ 新词引入门槛 + **ADR-0005 四处一致子串同步修订**(压测 Q2);全面审计(B 方案)记入 TODO
4. 哲学文件按学科视角重构(人因:为何信息真空;软工:为何纪律是护栏;运筹:决策成本与双轨对照)
5. 架构:显式规范优先级声明(只写一处)+ 入口收敛 + AGENTS.md 路由式引入
6. 设计产物落 `harness/design/repo/`(新建独立目录,不覆盖 methodology v3 设计套)

### 不做什么(scope 边界)

- 发布动作(单向门)、双 license 分区(ADR-0002)
- skill 内部机制与目录结构(OD-8 已决保留现状)
- OD-10(分发洁净)/ OD-12(grill 处置)/ OD-13/14(pilot 试点)在途事项
- **允许做**:术语变更带来的 skill description / 触发词措辞级同步(不涉机制)

## 核心场景 (V3)

- **AI 代理 / 新贡献者进入仓库**:入口文件(CLAUDE.md / AGENTS.md)→ 按改动选读 → 冲突时按规范优先级裁决——每类角色(方法论读者 / skill 使用者 / 维护者 / AI 代理)一条清晰路径(「项目A」的启动顺序 + 按改动选读模式)。
- **个人开发者读方法论**:从 README 入口 → 方法论文件(v4 自包含)独立成文,无需先读外部文档。

## 验收标准 (V4)

- **DoD-1(规范优先级)**:存在一份显式规范优先级声明(方法论主张(canonical)> ADR > CONTEXT 术语 > skill 规格 > 实操文件),且**只写一处**(防漂移,OD-8 教训)。
- **DoD-2(入口收敛)**:读者从任一入口(CLAUDE.md / README / 方法论文件)可达全部权威文档,导航不再三处各说各话。
- **DoD-3(回归安全)**:v3 保留为历史母本(内容不丢,沿 v2 先例);脱敏门 0 命中;现有链接检查不破。
- **DoD-4(术语)**:本次审计清单落地(保留/合并/替换逐词有结论)+ 新词门槛建立;CONTEXT 与全文一致。
- **DoD-5(受众一致)**:v4 全文适用对象表述一致为「个人开发者」,无残留团队表述矛盾。
- **DoD-6(dogfood)**:产物期 dogfood 用本仓库一次真实修订任务按新规范走通(实操文件轻量修订场景)。

## 风险与约束 (V5)

- **OD-4 母本同步**:v3→v4 升版须完整走母本标注流程(其他位置副本「开发副本,以 v4 为准」)。
- **脱敏(OD-1)**:新增/改动的 .md 全须 0 命中;设计文档自身用占位「项目A」。
- **多副本同步**:规范优先级 / 术语 / 入口表只允许一个权威副本;入口文件(CLAUDE.md + AGENTS.md)同步负担需控制在路由级(不复制全量规则)。
- **版本谱系**:v1→v2→v3→v4 快速演进,文件头谱系要清晰;v3 拆分(ADR-0007)刚完成即升版,历史记录需保留。
- **立论对称化成本**:第二支柱机制层 = 全新立论设计(非搬运第一支柱),工作量大,需独立设计。
