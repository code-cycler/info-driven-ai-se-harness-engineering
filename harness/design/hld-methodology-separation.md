## H1 拆分架构

### #1 拆分粒度:三块独立文件(采纳)

**决策**:方法论 / 哲学 / 实操三块各为**独立文件**,各自可独立修订。

被否决:
- 单文件分区标注(章节内分区段标「哲学/方法论/实操」)——不满足「相互独立方便改进」:改实操仍要动 canonical 单文件。
- 二文件(哲学并入方法论或实操)——丢了三块独立,且「哲学并入方法论」正是现状(不解决任何问题)。

### #2 三块命名与文件形态(采纳)

**决策**:
- 方法论文件**保留** `docs/methodology/methodology_v3.md`(版本线继续,见 #6)。
- 新增哲学文件、实操文件并列于 `docs/methodology/`:哲学文件 = `philosophy_v1.md`、实操文件 = `practical_v1.md`(2026-08-04 压测 Q9 拍板;全名+版本号规范,与 methodology_v3.md 一致)。
- 三块叫法 = **方法论 / 哲学 / 实操**(用户原话;「哲学」一词仓库内此前 0 出现,本次按用户用词引入为文档结构概念)。
- **导航链接版本策略**:链接带版本号(与 methodology_v3 先例一致);版本演进时导航链接同步更新(实操文件演进 = 轻量流程,顺手更新导航一行)。

### #4 §二 核心理念去向:保留在方法论文件(采纳 · 全案最关键分界)

**决策**:§二 核心理念(双支柱 + 机制层立论)**保留在方法论文件**。

理由:
- 核心理念是方法论主张的主体;移走则方法论文件失去立论根基,「独立成文」主张(#8)破。
- 锚点影响最小化:9 处外部引用中 **6 处零修改 + 3 处需改**(压测 Q1 修正,2026-08-04):CONTEXT:15 的 §1.2(§一 归哲学)→ 改指哲学文件、README:27 的 §8.3(§八 归实操)→ 改指实操文件、README:79「方法论本身的完整阐述见 methodology_v3.md」表述 → 微调(方法论文件是三块之一,「完整阐述」改为三文件并述)。skill 2 处(action-Q DESIGN.md §2.1/§5.3)零修改。
- ADR-0005 四处锁定(核心定义子串)与 README 双支柱表述锁定 §2.1,位置不变(#14)。

被否决:**§二 移哲学**——锚点 9 处全量重写 + 方法论文件失立论、自包含破;「哲学」块收编 §二 的直觉方案以锚点成本与立论完整性为由否决。

### #5 §五 Grill 决策方法论归属:方法论文件(采纳)

**决策**:§五 整章归方法论(§5.2–5.7 决策方法主体;§5.1 核心原则「不替人决策」+(a)(b) 盲区含立论成分但直接服务决策方法,随章保留)。

被否决:§5.1 拆去哲学——章节拆散,CONTEXT §5.3 锚点 ×2 与阅读连续性受损。

### #6 v3 文件身份与版本线(采纳)

**决策**:
- `methodology_v3.md` 保留为方法论文件,版本线**继续 v3**(本次是结构拆分非立论演进,v3 立论内容不动;升 v4 会混淆 v2→v3 的立论演进语义,且 v3 发布仅数日)。
- 哲学/实操 = **新文件 v1 起线**,各自独立版本线,后续可独立演进。
- v2 历史标注(「历史版本,以 v3 为 current」)不动。

被否决:三文件全升 v4(版本语义混乱)。

### #7 action-Q 机制论述候选并入(采纳)

**决策**:覆盖上轮 canonical 同步归档的「下一波候选③」(v3 正文 §4.2 是否展开 action-Q 机制论述,原安排 design-Q 修补)——实操文件补 **action-Q 机制说明**(触发词「对齐一下/确认细节/preflight」已有,缺「机制」论述:确认式问卷 = 非正式行动写操作前对齐细节防幻觉);§4.2 环节详解不展开(保持现状)。候选③消项。

被否决:本次不动、候选③仍挂 design-Q 修补(浪费结构改造窗口)。

## H2 组织与格式选型(含被否决项)

### #8 「独立成文/自包含」主张处置(采纳)

**决策**:方法论文件**保留**「方法论内核自包含,不依赖任何外部文档」主张(§二/§五 均在方法论文件 → 立论与决策方法自包含,读方法论不需先读哲学/实操);哲学/实操文件可引用方法论。
**压测 Q4 补充(2026-08-04)**:方法论文件开头加短「问题引子」段(3–5 行 vibe coding 失败叙事摘要 + 链接哲学文件 §一 全文)——§一(失败模式叙事)移哲学后,读者开篇即知问题背景,自包含成立。

### #9 canonical 归属(采纳 · OD-4 修订)

**决策**:**canonical 成员 = 方法论文件 + 哲学文件**(哲学含立论/原则,属「方法论主张」);**实操文件非 canonical**——实操修订走轻量流程(#15),不触发 OD-4 母本同步。这是「方便改进」的主要兑现。

被否决:三文件全 canonical(实操修订触发母本同步,独立改进落空)。

**连带**:OD-4 表述更新(canonical 从「methodology_v3」扩展为「方法论+哲学文件,实操非 canonical」),见 [ADR-0007](../../harness/adr/0007-methodology-three-way-split.md) 与 OD-4 修订注记。

### #10 License 边界(采纳 · ADR-0002 不触发修订)

**决策**:三文件均放 `docs/methodology/` 下 → 方法论文字 **CC-BY 4.0**,不触发 ADR-0002 修订;实操文件是「文字性使用指南」(§八 skill 使用时机、附录 A 工具规范——**指南文字**,非 SKILL.md 规格/配置),仍属 CC-BY。

**边界判据(记入 HLD,防未来混淆)**:实操手册 ≠ skill 配置——实操文件只放「怎么用」的文字说明;任何 skill 规格内容(SKILL.md、引擎副本、模板)必须放 `skills/` 下(MIT)。未来若实操文件需引用 skill 规格,用链接指向 skills/ 而非复制内容。

### #11 三文件篇幅(用户先验结论)

**决策**:**不设篇幅限制**(用户补充声明:「11 不做篇幅的限制」)。拆分后各文件篇幅随内容自然分布,不按预估约束(哲学块若偏短是立论层正常形态,方法论/实操块长是内容量使然)。

## H3 链接与术语契约(接口契约)

### #12 交叉引用策略(采纳)

**决策**:

- 跨文件引用(方法论 → 哲学/实操、哲学/实操 → 方法论)用**相对 Markdown 链接 + 节锚点**。
- **实现期全量 grep 核对跨文件 § 引用清单**(压测 Q2,2026-08-04):§1.2/§6.x/§8.3/§7.4-7.6/快速上手相关逐处判定同文件 or 跨文件,逐个改链接(已知实例:v3:73「见 §8.3」在 §零 引实操文件);拆完后跑一次**断链检查兜底**。
- CONTEXT/README/skill 外部锚点:**6 处零修改 + 3 处需改**(压测 Q1 修正,见 #4——CONTEXT:15 的 §1.2、README:27 的 §8.3、README:79 表述;ADR-0006 锚点全量重写先例仅在锚点章节跨文件移动时触发)。

## H4 发布与修订流程

### #15 拆分执行与修订流程分化(采纳)

**决策**:
1. **一次性拆分完成**:三文件落盘 + v3 文件头标注(拆分说明 + 哲学/实操文件链接)+ CONTEXT/README/CLAUDE 导航更新(如需)+ 脱敏门 0 命中 + 人审,不攒批次(窗口期成本最低,v3 发布未广泛引用——ADR-0006 先例)。
2. **修订流程分化**:
   - 实操文件:小步 commit、**免 OD-4 母本同步、免四处锁定检查**(轻量流程);
   - 方法论/哲学文件:维持现状(canonical 审查 + OD-4 母本同步)。
3. 「相互独立」收益 = 改实操不扰动 canonical、改哲学不扰动流程、改方法论不扰动操作细节。
