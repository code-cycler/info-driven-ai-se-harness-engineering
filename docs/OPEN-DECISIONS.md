## OD-1 脱敏发布门槛(单向门 · 需人逐行审查)

- **问题**:开源 push 后内容被 fork / 缓存不可真正撤回,脱敏不彻底 = 永久泄露。如何保证「脱敏干净」?
- **推迟原因**:脚本可写,但「语义泄露」(无项目名却仍可识别)只能人审,无法完全前置自动化。
- **当前占位方案**:发布前 DoD 三条全绿才 push——
  1. 脱敏检查脚本([scripts/desensitize.py](../scripts/desensitize.py))对全仓库 **0 命中**;
  2. **人逐行复审**脚本扫不到的语义信息;
  3. **脱敏报告**(改了什么)。
- **当前状态**:机械脱敏已完成(skills 39 处 + methodology 3 处,脚本 0 命中);**语义人审待做**——见建仓脱敏报告。
- **可逆性**:push 前完全可逆;push 后单向门。
- **重访触发条件**:每次发布 / 大更新前重跑脚本 + 重做人审;敏感词清单随发现新增。

## OD-2 「方法论可迁移到通用工具」是未验证假设

- **问题**:主张「在 Claude Code 上实践了 skill,但方法论可迁移」。然而 skill 强依赖 Claude Code 机制(AskUserQuestion / subagent / SKILL.md 加载),实际未在其他工具验证。
- **推迟原因**:经验缺口——没有在 Cursor / Cline / 其他 LLM CLI 上试跑过。
- **当前占位方案**:README 表述为「方法论理念工具无关、可迁移;skill 直接运行依赖 Claude Code 的三项机制——AskUserQuestion、subagent、SKILL.md;迁移到其他工具需适配」。
- **依赖边界已盘**:7 个核心 skill 的 SKILL.md 中,AskUserQuestion 出现 9 处、subagent 6 处——这两项 + SKILL.md frontmatter 触发是主要依赖。
- **可逆性**:双向门(README 措辞)。
- **重访触发条件**:① 有用户在其他工具适配成功 / 失败反馈;② 有人尝试移植;③ 出现「装不上」issue。

## OD-3 维护承诺对冲(单向门)

- **问题**:开源 = 公开维护承诺。skill 仍在迭代(delegate 试点、刚升 v2);issue / PR 不回 → 仓库变墓地。
- **推迟原因**:无法预判维护精力。
- **当前占位方案**:README 标 `experimental / 个人维护 / 不保证响应` + CONTRIBUTING + issue 模板;精力不足则退回「只发文章」。
- **可逆性**:发布单向门;承诺措辞双向门。
- **重访触发条件**:issue 积压超能力;方法论脱离试点稳定时上调承诺;连续无更新 > 3 个月考虑归档标注。

## OD-8 skill 引擎副本的开源呈现(已决)

- **问题**:QUESTIONNAIRE-FORMAT / PROCESSING-RULES 在三问卷 skill(design-Q / grill-Q / retro-Q)各持一份,均自标「design-Q 引擎复用件」;diff 证实 design-Q 与 grill-Q 的引擎文件**已漂移**——方法论 §11 第 17 条「引擎漂移」的活体证据。
- **决策**:保留三份现状 + DESIGN.md 声明漂移关系。不统一、不抽共享文件。
- **理由**:忠实呈现现状;统一 / 抽取需改 skill 内部组织,成本不在价值主线。版权作者原创,MIT 化无障碍。
- **可逆性**:双向门——不立 ADR(难逆转性不足)。
- **重访触发条件**:漂移引发困惑 / issue;或 design-Q 引擎升级后评估同步另两份。
