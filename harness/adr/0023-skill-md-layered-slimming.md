# ADR-0023: SKILL.md 精简分层与教训升格机制

- 状态:accepted(2026-08-19,grill-Q skill-family W01 Q8-A + 补充声明)
- 决策日期:2026-08-19

## 背景

SKILL.md 是每次触发即加载进上下文的**常驻 token 成本**(9 skill 合计 1140 行;long-running 344 / grill-with-docs 169 / design-Q 115 / grill-Q 107 / action-Q 99 / grill 96 / delegate 82 / doctor-harness 72 / retro-Q 56)。大量行数是带日期的教训注记与治理历史(如「上限 3 = 2026-08-08 用户裁决收紧,原 ≤2」「曾两次遗漏 ✍️ 自定义行」)。按第一支柱「有效上下文」逻辑,SKILL.md 应命中最小必要信息;出处与教训属按需读取的深层背景。压测补充声明进一步提出动态诉求:治理历史独立存放 + 索引导向 + **重复犯错才升格持久化**。

## 决策

1. **分层原则**:SKILL.md 只留**规则本体 + 自检条款**(如出题自检 grep 命令、强制执行类禁令);**出处 / 日期 / 教训叙述 / 裁决历史移 DESIGN.md**(按需读取,skill 目录内),SKILL.md 留一行索引导向。
2. **教训升格机制**:同一错误**重复发生(≥ 2 次)**→ 教训从 DESIGN.md 历史层升格写入 SKILL.md 规则本体(对人可读)或 CLAUDE.md / memory(对会话可加载);单次教训只在历史层,不占常驻上下文。升格即「这条教训配得上常驻位」的判据,取代「所有教训常驻」的现状默认。
3. **渐进执行**:按 skill 逐个迁移,优先 long-running(344 行);不搞一次性大扫除;每次迁移走铁律 8 双侧同步(`scripts/skills-sync-check.py`)。
4. **与 OD-10 关系**:本 ADR 是 OD-10「skill 分发洁净」的机制化路径——**移层而非删除**(信息不丢失,只换位置);OD-10 的「清洗非必要声明」由分层自然达成,重访时一并评估。

## 替代方案(被否决)

- **不动**(带日期注记是「为什么」的最小载体,删了规则变教条)——Q8-B,被裁决否决:token 成本是每次触发的经常性成本,出处可由 DESIGN.md + 索引行承载,可重访性不损失。
- **只挤修辞水分**(教训与出处全保留)——Q8-C(★推荐被否):作为渐进执行的顺手动作保留,但不作为终态;用户选择更彻底的分层终态。
- **教训全部常驻 SKILL.md**(即现状)——常驻成本随教训累积单调上升,与第一支柱「有效上下文」自相矛盾。

## 后果

- (+) SKILL.md 常驻上下文成本下降、有效上下文密度提升——第一支柱落到 skill 自身形态。
- (+) 教训有升级通道:重复犯错的教训才占常驻位,历史层不丢信息。
- (+) OD-10「分发洁净」获得可执行路径(移层而非删除)。
- (−) 迁移工程量 = 9 skill × 双副本;以渐进执行(逐 skill + 铁律 8)摊薄。
- (−) 规则与出处分离后,单读 SKILL.md 看不到「为什么」——靠 SKILL.md → DESIGN.md 索引行缓解;升格机制保证高频教训回流常驻层。
