## 接口契约

### 输入（调用方向 = 人显式手动触发）

- 触发词：项目地图 / 项目全景 / 掌握恢复 / 重新定向 / 我迷失了 / 重新生成项目视图。
- 信息源 = **抽象类别指引**（SKILL.md 内）：结构类（README / CLAUDE.md / 目录树）、治理类（CONTEXT / OPEN-DECISIONS / ADR / 设计套 / 问卷归档索引 / STATUS-LOG / CHANGELOG / TODO）、功能类（skills SKILL.md / 代码模块入口）；实例扫描清单外置——每次生成时实例化进产物「信息源指纹」清单，不进 skill 规格（抽象化裁决）。

### 处理契约（硬约束）

- **快照数据源 = 项目状态追踪文件头部**（遵循本方法论时 = TODO.md 头部「当前状态一行 + 下一步主线」，唯一权威源）；无此惯例的项目以 git 近况为准，并在快照段标注数据源与生成时点（grill W01 Q2 通用化）。直接引用转述，AI 不新增判断。
- **快照漂移自检义务**：重生成时检测状态追踪文件头部（本仓库 = TODO 头部）与 git 近况明显不一致 → 提示人先更新再生成；AI 不代写快照。
- **人因四原则（参数化）**：披露顺序 = 五段固定序（概览→结构→链路→状态）；图规模 ≤ 30 节点/图；单段目标 ≤ 15 行；下钻三级渐进（概览层无链接 → 结构层索引表 → 链路层「文件#节」锚点）。学科锚点一行（认知负荷、情境意识，引用 CONTEXT 既有定义，不新造术语）。
- **文风规范**：禁令（比喻性代称 / 文学修辞 / 情绪化形容，「定海神针」类为反例）+ 术语表选词原则（各行业系统工程通用交集，15–20 词，不正式引用单一标准；词表全量成文留 L2 一次生成）。

### 输出（硬约束标注）

- **单文件 `harness/PROJECT-OVERVIEW.md`，总长目标 ≤ 250 行（含图）**——超过即精简（详略分级 / 链接外移），「减的负荷 > 加的负荷」取向的产物侧硬约束。
- **五段式结构（固定序）**：① 项目定位一句话 → ② 结构全景（BFS 总图 + 区块索引表）→ ③ 决策脉络（关键决策时间线）→ ④ 当前状态快照 → ⑤ DFS 深链视图。
- **文件头三件套**：生成时间戳 + 信息源指纹（源文件清单：路径 + 每文件一行摘要；不用 hash）+ 「以源文件为准，本文件为派生视图」声明。
- **图规格**：
  - 类型学：节点两类（功能/结构节点、信息/工件节点）；边三类（包含、依赖、流转·触发）；BFS 以包含边为主、DFS 以流转·触发边为主；
  - BFS = 层次分解图一张（项目根 → 层 → 每层功能；节点预算 ≤ 30：根 1 + 层 3–6 + 每层功能 3–5，超限按层聚合，聚合优先保每层功能完整）；
  - DFS = 每功能一条逻辑链（功能 → 内部逻辑/子功能 → 依赖 → 落点工件），关键功能全链 + 其余功能短链（一行：功能 → 落点）+ 索引表；「关键功能」判据 = 承载当前主线/高风险（从 TODO 主线 + 验收锚点反推）；图数上限 8–12，每图 ≤ 30 节点；
  - 链接承载：图内短名/编号 + 图旁索引表（markdown 相对链接，文件级 + 关键链「文件#节」锚点；mermaid 节点内链接跨渲染器不稳，不用）。
