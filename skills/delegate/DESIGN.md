# delegate skill · 设计决策记录

> 与家族其他 skill 的 DESIGN.md 同级:记录设计权衡与来源。本 skill 当前为 **dogfood 试点版**,试点反馈回宿主项目的「决策下放」OD 条目。

## 来源

- 2026-07-25 宿主项目 grill-questionnaire W01(某决策下放压测问卷)压测用户提案「下放部分简单决策权给 AI」后的产物。
- 关键既有事实:宿主项目的判断权原则(只保留产品/工程/安全/合并四类);产品层已有受限 AI 判定(auto-approve、review LLM);权限规则「Agent/LLM 只能收紧不能放宽」、预设规则「可建议不可自行应用」。本 skill 是这些原则在**流程层**的同构镜像。

## 设计决策

| # | 决策 | 理由 | 被否决项 |
|---|------|------|----------|
| G1 | 机制 = 固定白名单,分类权完全在人 | 误判面收敛为「人枚举时的遗漏」而非运行时逐例误判;与「只能收紧不能放宽」同构 | 否决窗(AI 自判 + 事后否决);风险分级镜像 L0–L3;AI 自分类 + 置信度阈值 |
| G2 | 治理文件与日志分离(delegation.md / delegation-log.md) | 治理文件变更须人发起,日志高频追加;混在一起会让 Changelog 被日志淹没 | 单文件日志区 |
| G3 | 位置 = 项目根,纳入版本控制 | 治理文件必须随项目走、可 diff、可审计;不同项目下放范围不同(Q8 自定义:工程启动初始枚举,随后动态调整) | 全局一份(忽略项目差异);`.claude/` 隐藏目录(可见性差) |
| G4 | 双层收回:单条目触发条件 + 整体开关 | 局部误判与「试点失败」是两种事件,缺一则过度反应或反应不足 | 只整体开关;只单条目 |
| G5 | 禁区优先于白名单 | 边界重叠是必然的(如「格式排版」碰到安全文件);默认向安全侧收敛 | 白名单优先;逐例问人(疲劳依旧) |
| G6 | ~~preview 级文档作为可选交互~~ **superseded(2026-07-25 dogfood round 1)**:preview 迁移为 design-Q 强制阶段步骤——**round 2 演进为独立 W00 波**(勾=采纳/留空=不采纳、无 🤔,与 W01 分开交付),规格单源在 design-Q | 「可选 + 模糊触发 = 从不发生」(round 1 零触发)→ round 2 进一步发现「W01 头部节」形态仍混在一起,拆独立 W00 后 项目B 实测 preview 预答率 ~100% | 留在 delegate 内作可选节(零触发的直接原因) |

| G8 | dogfood 场域 = 其他项目,不先在 项目A 本体启用 | 避免试点数据污染本体治理;反馈回「决策下放」OD 条目,再决定是否固化进 项目A 铁律措辞 | 直接在 项目A 启用 |
| G9 | 整合形态 = delegate 独立 + design-Q 显式调用契约,不合并(2026-07-25 dogfood round 1) | 痛点是「触发不确定」,契约即可消除;合并让非 design-Q 场景(纯实现期、不跑 design-Q 的项目)失去下放能力,且扩大引擎三副本同步面 | 完全合并进 design-Q(用户 dogfood 初提案,压测后改选) |
| G10 | 放权时机 = init 起草可早,激活统一定在 vision 阶段闸门(2026-07-25 dogfood round 1) | dogfood 已有机验证一次(vision-w01 补充声明用户选「vision 定稿后一并审查」);vision 产物(范围、禁区知识)是审查白名单的最佳上下文 | 工程一开始即激活(初版设计,触发不确定的来源);init 也延后到闸门(雏形决策失去覆盖) |
| G11 | D7 工程判断「HLD/LLD 框架内有条件下放」作模板候选行,默认 disabled(2026-07-27 dogfood round 2) | 项目B D7 stage0 单点未偏离但**无留痕证据**(log 缺失)、无边界事件(某结构性种类未触发);「分类权在人」= 提供实战文本,激活权逐项目在人,默认关闭控制敞口。待 round 3(阶段 4 结构性种类扩展 + 留痕数据)再定性 | 模板默认 active(把未验证边界类直接设默认,激进);只记案例不进模板(下个项目重新发明轮子) |

## Dogfood round 1(2026-07-25,项目C 设计期)

压测归档:宿主项目某 dogfood 问卷;结论同步于宿主项目「决策下放」OD 条目。关键发现:

- delegation-log **0 条**;dogfood 只跑了设计阶段(项目无代码目录),D1–D6 未遇出现场景。根因 = **决策面错位**:设计期判断负担在问卷作答(内容决策,不可下放),白名单覆盖实现期决策类——白名单尚未被真正测试,原样保留待实现期验证(「太保守」降级为次要观察项)。
- 「触发流程不确定」属实:design-Q 全文 0 处 delegate 引用,dogfood 衔接靠 vision-w01 补充声明临时接线 → G9(契约化)、G10(放权时机)。
- preview 全程零触发(「可选 + 模糊触发」)→ G6 superseded,迁移为 design-Q 强制步骤。
- design-Q 无环境现实验证步骤(dogfood 实证:SFML 版本、字体路径迟至 grill 阶段才被迫修订)→ design-Q 增加环境验证子步骤。
- **下轮度量四项**:每阶段判断轮次数(问卷波数×题数)、preview 预答率、delegation-log 条数(实现期)、逃生舱使用率。

## 待 dogfood 回答(round 3,实现期 + 边界事件)

- 首版白名单(D1–D6)在 coding 场景的真实覆盖率与误判率;「太保守」观察项届时评估。
- D7(项目B 治理创新)在阶段 4 某结构性种类等结构性扩展场景的边界判定是否清晰;留痕补齐后「框架内下放」是否真不偏离 HLD/LLD。
- 「建议升级」的频率与质量(是否成为新的决策疲劳源)。
- preview(W00 独立波)的真实减负效果——round 2 预答率 ~100%(观察点:默认值质量高 vs rubber-stamp,待更多样本)。
- log 存在性检查机制(G12)是否消除留痕漏执行。
- 收回触发条件的粒度是否可操作(「1 次」是否过严/过松)。
