## 目标与受众 (V1)

**核心目标**:补全第一支柱的「机制层」——把「对抗 AI 幻觉式决策」从 methodology_v2 §2.1 的一句隐性修饰,提升为显性立论,作为「返工」「有效上下文质量」两个外围框架的根因。立论回归作者本意:

> 传统 vibe coding 中**背景信息交代不全** → AI **自以为是、自作主张决策** → **幻觉** → 故方法论采用**问答方式逐步对齐需求**。

**受众**:沿用 v2「1–5 人小团队/个人开发者」,范围不变。v3 引入 vibe coding 为首要治理对象后,叙事重心偏向个人开发者/AI-heavy 用户,开篇引子换场景。

## 核心场景 (V3)

v3 §1 或 §2.1 以 **vibe coding 失败场景**为开篇引子(背景交代不全 → AI 自作主张 → 幻觉),取代 v2 §1.1「等 PM/QA」传统场景的主引子地位。传统多人 SDLC 降为对照(讲 AI 替代角色那部分仍有价值,保留)。

双靶子:vibe coding 占主叙事,传统 SDLC 次要——**配比细节 hld 阶段定**。

- **DoD-1(核心)**:v3 §2.1 存在一处可被独立引用的正面因果论断——「背景缺失 → AI 在信息真空幻觉式自作主张 → 问答对齐是对抗此机制的直接手段」。

## 风险与约束 (V5)

- **旧框架不被否定**:三层叠加(返工=症状层 / 有效上下文=度量层 / AI 幻觉决策=机制层),旧框架挂机制层下,读者不觉被否定。
- **章节锚点稳定**:v3 保持 v2 章节编号,机制层用小节(§2.1.x)而非重排,避免 CONTEXT/README/CLAUDE 锚点失效。
- **OD-4 母本同步**:v3 发布检查清单纳入「作者其他位置副本标注'开发副本,以 v3 为准'」。
- **脱敏(OD-1)**:v3 新增内容(尤其 vibe coding 场景若举例)发布前 [scripts/desensitize.py](../../scripts/desensitize.py) 0 命中 + 人审;「项目A/B/C」占位沿用。
