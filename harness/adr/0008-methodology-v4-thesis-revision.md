# ADR-0008: 方法论 v4 立论重构(受众收窄 + 第二支柱机制层对称化)

- 日期:2026-08-05
- 状态:accepted
- 来源:repo 级 design-Q(参考「项目A」架构优化;vision W01 Q1/Q2/Q3 + hld W01 Q5)+ grill-Q 压测回灌(Q5 对称化增量 / Q6 受众重述)

## 背景

methodology_v3(2026-07-29 发布)补全第一支柱机制层后,方法论在自身使用中暴露三问题:受众定位过宽(1–5 人团队 + 个人两头写,§零 表述分散)、术语膨胀(8 个自造词)、第二支柱权重不足(双支柱均衡表述下「驾驭工程」只有叙述性论述,缺与第一支柱对称的机制层立论)。v3 三块拆分(ADR-0007,2026-08-04)刚完成,文档体系进入稳定期,窗口期改造成本最低。

## 决策

1. **方法论文件 + 哲学文件升 v4**(沿 v1→v2→v3 立论级版本演进惯例;实操文件不升版,随同步走轻量流程)。v3 移入 docs/methodology/archive/ 标「历史版本,以 v4 为 current」。
2. **受众彻底收窄为个人开发者**:§零 适用对象只写个人,团队场景一句带过;机制内容(分工 / delegate / AI 替代角色)保留重述为「个人 × AI 代理」视角——受众是读者画像,不是内容过滤器。
3. **第二支柱机制层对称化**:§2.2 补「无护栏 → AI 产出悄悄劣化 → 返工。工程纪律是护栏」机制层立论,与第一支柱机制层(背景缺失 → 幻觉式自作主张)对称。**只建机制层,不建度量/症状层**——劣化的度量与症状与第一支柱共享(有效上下文稀释 / 返工),两支柱是同一系统的两面。
4. **哲学文件学科化**(v4):§一 挂人因工程视角(情境意识 / 信息加工缺陷)、§六 挂软件工程视角(纪律护栏)、新增 §七 运筹学视角(决策成本模型 / 双轨对照)。章节号保持(锚点稳定)。

## 替代方案

- **v3 修订不升版**:内容级立论变化与「版本 = 立论演进」惯例不符,谱系混乱。否决。
- **第二支柱全三层对称**(机制/度量/症状):度量层(纪律执行度的度量)与症状层(代码劣化)映射牵强,强建稀释「对称 = 各有机制层」本意。否决(压测 Q5)。
- **受众收窄但团队附录专章**:多一个章节维护负担,违背「收窄」意图。否决(用户 W01 Q2 选彻底收窄)。

## 后果

- (+) v4 立论更聚焦:个人受众 + 双支柱各有机制层,叙事重心清晰。
- (+) 哲学文件学科化后,术语与成熟学科可对话(人因 / 软工 / 运筹)。
- (−) v3 归历史母本,OD-4 母本同步需执行(其他位置副本标注「开发副本,以 v4 为准」)。
- (−) 术语全保留(ADR-0010),立论核心词(信息真空 / 背景缺失等)不变,全文一致性通过回归验证。
