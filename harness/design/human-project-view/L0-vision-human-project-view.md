## 目标与受众

- **目标**：新增横切工具型 skill（**proj-overview**，家族第 9 个，不进 5 环节闭环主路径、不持问卷引擎副本、无 AskUserQuestion 交互），为宿主项目生成一份**人读项目掌控视图**单文件——从既有治理/结构文件派生，**线性叙述 + 关系图双形式**（同一项目复杂关系图的两遍遍历展开：BFS 层次分解图 + DFS 每功能逻辑链图，规格见 L1「图规格」节），使项目掌控者以最小认知成本恢复/建立对整个项目的掌控。
- **受众 = 项目掌控者本人（单一受众）**：服务于「从不同时空条件切入推进项目的人」；不为外部采用者优化（外部视角由 README 承载）。
- **设计取向（回应挑战三的机制；grill W01 Q6 由「判据」降格——不可测不装可测，失忆测试人判为唯一实证锚）**：「视图派生」而非「文件削减」——不删并既有 harness 文件、不新增权威源，只加一个派生视图层，用「降低人的检索/整合成本」对冲「文件数量不变」；**减的负荷 > 加的负荷**作为全程设计取向（L1 显式化为约束项）。
- **信息传递立场（W00 补充声明）**：skill 宗旨 = 让用户**尽可能多地掌握项目信息、做好信息传递**；呈现设计需考虑**人因工程**（认知负荷 / 情境意识，接 CONTEXT「项目学科地图」人因工程行；落实方式〔W01〕）。
- **方法论挂接深度 = skill 先行、canonical 缓行**：「harness 文件人读/AI 读职责分野」写入 canonical 方法论/哲学属 canonical 修订候选，走独立 canonical 审查流程（grill-Q 压测或人逐行审 + 用户批准），不随本 feature 顺手改。

## 范围

### 做什么

- 扫描宿主项目治理/结构面，生成一份视图文件（**产物唯一，单文件**——拆分即打回「文件太多」原点）。
- 线性部分 = 五段式「一页掌控」：① 项目定位一句话 → ② 结构全景（图 + 区块索引表）→ ③ 决策脉络（关键决策时间线）→ ④ 当前状态快照（主线/进行中/下一步；数据源 = **TODO 头部「当前状态一行 + 下一步主线」唯一权威源**，直接引用转述，AI 不新增判断——W01 Q10）→ ⑤ DFS 深链视图。
- 图部分 = 项目复杂关系图的两遍遍历展开：BFS 层次分解图 + DFS 每功能逻辑链图；混合类型学（节点两类：功能/结构节点、信息/工件节点；边三类：包含、依赖、流转·触发）+ 分图策略（详见 L1「图规格」节，W01 Q2–Q5）。
- 文件头新鲜度自声明三件套：生成时间戳 + 信息源指纹（源文件清单或 hash）+ 「以源文件为准，本文件为派生视图」声明（对齐 en 镜像「中文源为唯一 canonical」语义）。
- **skill 规格抽象化**（W00 补充声明 + W01 Q7 裁决「完全抽象 + 实例外置」）：面向一般「多层次、各层次多功能」项目，SKILL.md 只写通用规格（扫描项目的结构/治理文件面 + 抽象的信息源类别指引）；本仓库（dogfood 实例）特定扫描清单（CLAUDE.md / docs 四大块 / harness/adr / harness/design / 问卷归档索引 / TODO / STATUS-LOG / 根 CHANGELOG / skills 各 SKILL.md；**不扫** en/ 镜像、waste/、git 内部状态）放产物文件的「信息源指纹」清单里，每次生成时实例化，不进 skill 规格。

### 明确不做什么

- 不做 AI 会话入口（CLAUDE.md 职）/ 对外宣传（README 职）/ 变更记录（根 CHANGELOG 职）/ 行动追踪（TODO 职）/ 内部状态史（harness/STATUS-LOG 职）——五文件分工边界显式写进 skill 规格。
- 不新增权威源、不参与规范优先级裁决（只读派生层）。
- 不做 HTML 变体（首期与 L2 均无此任务；如需引入另立 feature 重访——重访触发 = md 版失忆测试通过且多环境渲染痛点实证，grill W01 Q1 消除「L2 可选」悬空承诺）；首期格式 = md 单格式（mermaid 代码块，多环境兼容靠 GitHub 原生 + VSCode 插件兜底；HTML + CDN mermaid@11 渲染链路已于 2026-09-22 实测通过备查）。
- 不做自动更新（无 git hook、无会话自动跑；**手动触发重生成**，覆盖式，git 历史即版本留痕，不做 `_vN` 递增）。
- 不进校验脚本（**漂移治理宽松**：视图过期不算 harness-check 违规、无强制同步义务——区别于 en 镜像 hash 强同步；防止本 skill 变成第四个提交前检查脚本）。
- 不随本 feature 修改 canonical 方法论/哲学文件。

## 核心场景

1. **失迷失忆恢复**：隔 ≥3 天或新会话切入，只读该文件（+按需点入链接）恢复项目掌控。
2. **定期重定向**：项目演进后主动调用 skill 重生成视图，刷新心智模型。
3. **复杂项目信息传递**：多层次多功能项目的关系图两遍展开（层次分解 + 功能逻辑链路），按人脑获取知识 的难易度组织信息。

## 验收标准（可独立验证条目式）

1. **失忆测试**（核心锚点）：用户隔 ≥3 天或新会话切入，只读该视图文件（+按需点链接）**≤15 分钟内能回答三问——当前主线 / 关键决策所在文件 / 下一步；三问全达 = 通过，两达 = 部分通过记回评**（grill W01 Q7 细化）——由用户真实执行判定，AI 自评不算数（对齐 OD-13「人类试玩通过才升级」）。
2. **本仓库 dogfood**：生成首份视图（基线 = 挑战三实证：238 md / 25 ADR / 28 OD / TODO 455 行），用户反馈「掌控感提升」。
3. 产物规格符合性：单文件；文件头三件套齐全；图中关键节点附源文件相对链接；图规模策略符合 L1 规格。
4. **skill 本体元成本**：SKILL.md < 100 行、无引擎副本、无独立模板文件（生成逻辑内嵌）。
5. **全仓联动完成**：README / 项目 CLAUDE.md「8 个核心 skill」表述与协作图更新为 9；HARNESS-RULES 新增「人读视图」产物类目并留痕；TRANSLATABLE en 镜像义务评估；skills-sync-check 双侧同步。
6. 挑战报告 #三 反馈行已填（2026-09-22 随 W00 处理执行）。

## 风险与约束

1. **自指风险**：为治膨胀加 skill 反加重膨胀——对策：skill 本体极简（验收 4）+「元成本」为 L1 显式契约项。
2. **误导风险**：过期图/错图致错误决策（错误图比没有图更危险）——对策：三件套 + 图节点带源链接，人按图决策前可一键核对源文件；**禁止按过期图做单向门决策**（文风与免责声明显式警示）。
3. **抽象化张力**（已决，W01 Q7）：skill 规格完全抽象 + 实例外置——通用规格进 SKILL.md，实例扫描清单进产物文件信息源指纹；「规格绑死实例」风险消除。
4. **人因工程约束**（已决落实方式，W01 Q8）：SKILL.md 内嵌「人因设计原则」短节——信息分层（概览→结构→链路→状态的披露顺序）/ 渐进披露（一页掌控→按需下钻链接）/ 图规模上限（约 30 节点/图）/ 线性认知顺序四条 + 学科锚点一行（认知负荷、情境意识，引用 CONTEXT 既有定义，不新造术语）。
5. **文风约束**（已决落实方式，W01 Q9）：SKILL.md 内嵌文风规范短节——反向禁令（禁比喻性代称、文学修辞、情绪化形容，「定海神针」类为反例）+ 正向术语表（系统工程通用词汇约 15–20 词：模块/接口/依赖/基线/追溯性/验证/配置项/职责/边界等，取各行业通用交集，不正式引用单一标准）。
6. **图遍历语义规格**（已决，W01 Q2–Q6）：混合类型学（节点两类、边三类；BFS 以包含边为主、DFS 以流转·触发边为主）；BFS = 层次分解图（逐层展开到功能粒度）；DFS = 每功能一条逻辑链（功能→内部逻辑/子功能→依赖→落点工件），深度边界 = 落点工件级（文件为主，关键链可到「文件#节」锚点，W01 Q6-C）；分图策略控规模（W01 Q5-C）。

## 动机

- **实践感受（用户原始）**：当前 harness 文件同时承担人读与 AI 读双职责——对 AI 是重建上下文继续工作的保障（须严谨详细），对人却是「太多太长」：不同时空条件切入推进时，人脑对项目的掌控理解反而更难 = **人的上下文、注意力不足**（与 AI 的有效上下文瓶颈对称的人侧镜像）。
- **回应挑战三**（哲学 v7 挑战报告：元系统膨胀——治理工具复杂度超过被治理对象，25 ADR / 28 OD / 238 md 的「哪份是权威」成为最大信息断层）：以视图派生对冲，不削减文件。
- **方法论级改进**：「人读/AI 读职责分野」机制化——canonical 现状（methodology_v5:281 只论述面向 AI 的重建上下文；:500 面向未来读者的 ADR 门槛）无此分野的系统论述，本 feature 在 skill 层先立实践，canonical 挂接待 dogfood 验证后走审查（修订候选进 TODO）。
- **空白实证**（探索报告 2026-09-22）：现有全局性文件无「横向结构全景 + 认知重建」职责格；全仓 mermaid 图全部为流程/因果/协作图，零「项目全景图」尝试。
