# 层级骨架(design-questionnaire 模板 · LN 制)

> **导览块**
> - 本层位置:design-Q 模板文件(层级制,取代旧三阶段骨架);布局侧规则(目录/校验)见 doctor-harness HARNESS-RULES.md 第七节
> - 覆盖:四部分——① 总则(职责模型/命名/形态)② 最小必含总览 ③ 层模板库 ④ 协议集
> - 上下游依赖:SKILL.md 主流程引用本文件;long-running 从 L2(或最低构建层)反推 feature_list
> - 契约项声明:第二部分最小必含与第四部分协议集为硬约束,层文件不得偏离;反简化声明约束**内容**不止结构

> 🔧 **反简化声明**:「最小必含」约束的是**内容**,不止结构——每项子项内容须可被实现期直接执行(非占位、非「见后」、非一句话带过)。填了子项标题但内容空泛(如「被否决项」填「无」、「回归验证」填「测试通过」)不算满足。骨架是规格,不是提纲。
>
> 🔧 **反形式主义声明**(设计原则 1):每个机制进层文件前必答「解决什么实际问题?没有它会怎样?」答不出 = 不写。层文件按需生成,纯空层不预建。

## 第一部分 · 总则

**混合制职责模型**:
- **L0 固定 = 目标层**(命名以 `vision` 起头):承载目标/范围/核心场景/验收标准/风险约束/动机——L0 恒在,不可坍缩(验收缺失 = 无限打磨);
- **L1+ 浮动 = 职责自声明层**:层号只表深度序,职责由该层文档自声明(导览块首行);常用模板(L1-contract 契约层 / L2-build 构建层)作默认参照,非强制映射;
- 大项目/多子系统可加 L3+ 深化层。

**层分配原则**(来源 = grill-Q first-principles 实测反馈,证据 = 2d rts 项目):**默认每层负责一个功能;仅当某部分内容明显较少时才并入相邻层**。同层多功能会诱发信息被省略/丢失——实测「默认三层 + 同层多任务」已出现该症状;宁可多一层,不让功能挤同层。

**命名规范**:`L<N>-<功能1>-<功能2>….md`——尾缀 kebab-case 且覆盖该层**所有主要功能**(一眼可识);示例 `L0-vision-scope-acceptance.md` / `L1-contract-interface.md` / `L2-build-dod.md`;目录 `harness/design/<feature>/`。

**两种形态**(定模时选定,中途增层可切换):
- **多文件形态**(默认,中大型):每层一文件;每层独立 W00(决策默认值清单按层生成);
- **单文件多节形态**(小项目/小 feature/小 action):一文件内 `## L0-vision-…` 节标题分节,文件头做全层导览;**整文件一个 W00**(全层决策默认值合一按层分节列)——防 W00 碎片化。

**层内组织原则**(retro 规格反馈):LN 文档**不做多功能大融合**——层内按「功能相近或篇幅较小的部分合在一起」组织;大功能显式分节(或按需拆层),防单层文件膨胀为杂烩。

**表述要求**(retro 规格反馈):层文件条目用完整句表述,避免过度压缩的简略语——层文件是跨会话重建上下文的 source of truth,简略语省下的行数会在下游变成误解成本。

**旧术语别名**(兼容既有引用):VISION = L0;HLD = L1(契约语义);LLD = L2(构建语义)。历史文档不重写,新产物用 LN 制。

**层内波次沿用旧制**:W00 preview → W01+ 正式题 → 覆盖清单 → 层闸门;骨架必答项按层取(见第二部分),阶段词汇统一映射为层。

## 第二部分 · 最小必含总览(置顶核对表)

| 层 | 最小必含(缺一即空骨架) | 反简化锚点 |
|---|---|---|
| **L0-vision**(恒在) | ① 目标与受众 ② 范围(明确不做什么)③ 核心场景 ④ 验收标准(可独立验证条目式)⑤ 风险与约束 ⑥ 动机(feature 必答/init 选答)⑦ **L0 自检节**(五信号清单,见协议 5) | 验收标准必须「按可独立验证的条目写」——写法约束,long-running 单层反推依赖此 |
| **L1-contract**(契约模板,若生成) | ① 模块/边界与职责 ② 接口契约(数据格式/协议/调用方向 + 硬约束标注)③ 全局选型 + 被否决项(≥1)④ 部署运维 ⑤ ADR 识别(三条件核对)⑥ 导览块**契约项声明** | 契约项声明列出本层哪些项是下层硬约束(裁决协议的实例落点) |
| **L2-build**(构建模板,若生成) | ① 阶段拆分(可独立交付/验证 + 依赖链)② 每阶段详细设计 ③ 接口规格(入参出参/错误码)④ 每阶段 DoD(可脚本化优先 + 回归验证)⑤ 依赖与预估 | 阶段拆分是 long-running feature 反推源;「不能独立验证 = 粒度太粗」 |
| **自声明层**(L1+ 任意) | ① 导览块(职责自声明 + 契约项声明)② 该职责域的核心内容(按语义就近对标 L1 或 L2 的最小必含密度)③ 与上下层的依赖关系 | 内容密度不得低于对标模板(防「自声明」沦为减配后门) |

## 第三部分 · 层模板库

### L0-vision 模板(固定)

```markdown
# L0-vision-<功能词>.md · <feature 名>
> 导览:① 本层位置与职责(= 目标层) ② 覆盖范围 ③ 上下游依赖(下游层/实现期依赖本层验收) ④ 契约项声明(本层验收标准为全链硬约束)
## 目标与受众 / ## 范围(做什么;明确不做什么) / ## 核心场景 / ## 验收标准(可独立验证条目式) / ## 风险与约束 / ## 动机
## L0 自检节
- [ ] ① 多模块/多子系统? ② 外部依赖 ≥ 2 类? ③ 跨会话实现(需 feature_list)? ④ 验收含性能/安全门槛? ⑤ AI 判定构造细节不足以直接实现(建议信号:须附「哪些构造细节缺失」具体理由)
- → 任一命中 = 建议增层(**人在闸门拍板**);全不中 = 单层交付合法
```

### L1-contract 模板(默认参照)

```markdown
# L1-contract-<功能词>.md
> 导览:① 位置与职责(契约层:跨实现阶段稳定的架构骨架) ② 覆盖 ③ 上下游(继承 L0 验收;约束 L2) ④ 契约项声明(接口契约/全局选型/模块边界 = 下层硬约束)
## 模块与边界(模块表或架构图;每模块职责一句话) / ## 接口契约(硬约束标注) / ## 全局选型(选型表含被否决列) / ## 部署运维 / ## ADR 识别
```

### L2-build 模板(默认参照)

```markdown
# L2-build-<功能词>.md
> 导览:① 位置与职责(构建层:分几步建/每步做什么/何时算完) ② 覆盖 ③ 上下游(受 L1 契约约束) ④ 契约项声明(阶段 DoD 为验收硬约束)
## 阶段拆分(阶段表 + 依赖链 + 每阶段独立 DoD) / ## 详细设计(按阶段列内部结构) / ## 接口规格 / ## 每阶段 DoD(脚本化优先 + 回归) / ## 依赖与预估
```

### 自声明层模板

```markdown
# L<N>-<自声明功能>.md
> 导览:① 位置与职责(**本层自声明:<一句话>**) ② 覆盖 ③ 上下游(继承上层契约:<列>;约束下层:<列>) ④ 契约项声明(<列>)
## <按自声明职责组织,内容密度对标 L1 或 L2>
```

### 单文件多节形态

文件头 = 全层导览(各层位置/依赖/契约项一行总览);正文按 `## L0-vision-…` / `## L1-…` 分节;**节内最小必含与文件间同规**;W00 = 整文件一个(按层分节列要点)。

## 第四部分 · 协议集

1. **层间判别(三问)**:① 随实现推进会变吗?(会 → 越往下层)② 边界契约还是内部细节?(契约 → 契约层)③ 目标/验收还是手段?(目标 → L0)。判别结果随层文件落盘(一条决策一个家);跨层引用「见 L1-contract#锚点」。

2. **层间裁决**:**上层契约优先于下层细节**——L(n) 契约是 L(n+1) 硬约束;下层改上层契约必须走 ADR-0021 治理性偏差路径(暂停 → 更新上层 → 再继续)。双落点:本协议为总则;各层导览块「契约项声明」为实例。

3. **插层协议**:触发(实现受阻/契约需细化/新子系统)→ 位置(默认底层追加;确需中间层时新层继承上层契约并重过闸门)→ 新层独立 W00 → 处理报告留痕(触发原因/影响面/受影响下层清单)。

4. **阶段(层)回退协议**:任一层发现上游前提失效 → 暂停下游 → 失效项二分(作废/仍有效,显式标注)→ 回上游补波 → **只重过受影响层闸门**(非全链重跑);已归档问卷不动,回退事实记处理报告。

5. **L0 自检(五信号,任一命中 → 建议增层,人在 L0 闸门拍板;全不中 → 单层交付合法)**:① 多模块/多子系统;② 外部依赖 ≥ 2 类;③ 跨会话实现(需 feature_list);④ 验收含性能/安全门槛;⑤ AI 判定构造细节不足以直接实现(**建议信号**:须附具体缺失理由;AI 判定只作触发建议,与「AI 自评不能单独证明通过」对齐)。

6. **形态 × 协议适用矩阵(⚠ 确认后落地)**——非默认形态下各协议的操作化,未列组合按标准形态执行:

| 形态 × 协议 | 层闸门 | L0 自检五信号 | 回退协议 | 插层协议 | TODO 四时机 |
|---|---|---|---|---|---|
| **标准多文件** | 每层过闸(协议现行) | L0 闸门同时过(现行) | 只重过受影响层(现行) | 默认底层追加(现行) | 照常 |
| **轻量模式** | L0 单层交付后过一次层闸门(简化版:覆盖清单 + 补充询问合并) | **照跑**——跑 = 建议增层;人拒绝增层 = 显式接受单层(拍板记处理报告),单层合法性由人拍板而非免检 | 单层无回退对象;上游前提失效 → 重开 L0(作废/仍有效二分同规) | 不适用(单层);若插层即退出轻量转标准形态 | 行动项照写 TODO(轻量只免归档,不免行动项) |
| **单文件多节** | 每层节完成后逐节过闸 **或** 全部完成后一次性按节过闸(定模时选定并在文件头导览声明) | 文件头全层导览处标注 L0 自检结果 | 「只重过受影响层」→ 只重过受影响**节**;节内作废/仍有效二分在节头以 `> 回退注记` 标注,不动其他节 | 节中插层 = 新节插入文件对应位置,继承上层节契约并重过该节闸门 | 照常 |

## feature 模式裁剪(沿用)

- **前置**:探索现有代码库与文档必须;涉及现有行为的题必须附出处(文件:行)。
- L0:目标/范围/场景/验收保留(聚焦功能本身);风险聚焦与现有系统冲突;动机必答。
- L1:重点变为「与现有架构的契合点与差异」;模块边界缩为「新增/修改哪些」。
- L2:不裁剪;每阶段 DoD 必含「不破坏现有功能」回归验证。
