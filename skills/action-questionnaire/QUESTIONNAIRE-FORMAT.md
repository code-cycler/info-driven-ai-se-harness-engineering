# 问卷格式规范(design-questionnaire 引擎 · 复用件)

> ⚠️ 本文件是 design-questionnaire 引擎的**第 4 份副本**(2026-07-30 从 design-Q canonical 复制,含 W00 preview 节——grill-Q / retro-Q 副本无此节,diff 实证)。design-Q 为 canonical;另有 retro-questionnaire、grill-questionnaire、action-questionnaire(本)共四份。修改需考量四方同步,漂移需声明(见四处 DESIGN.md)。
> **本 skill 的有意分叉**(区别于既有三份的意外漂移,2026-07-30 grill-Q W01 Q6/Q15 裁决,OD-11):
> 1. W00 = **confirm-list(细节确认清单)**,语义从「决策默认值 + AI 默认倾向」(生成式:AI 提议方案,人采纳)改为「行动细节 + AI 的理解」(确认式:AI 汇报理解,人核对)。模板与规则 3/8/13 相应改写。
> 2. 文件命名 `confirm-<slug>-w<NN>.md`(无 stage 概念——本 skill 无设计阶段)。
> 3. confirm-list 要点数建议 **5–20**(行动轻量,从 design-Q 的 10–25 收窄)。

## 文件约定

- 活动问卷目录:`harness/questionnaires/`(懒创建,首次生成问卷时才建)
- 命名:
  - `confirm-<slug>-w<NN>.md`(slug 为行动短名,kebab-case;NN 从 00 递增,**w00 = confirm-list 独立波**,w01 起为正式题波)
  - 同 wave 超题量拆子波:`confirm-<slug>-w<NN>a.md`、`…b.md`
- 归档:处理完毕移入 `harness/questionnaires/archive/`,文件名不变,只移不删

## frontmatter(必填)

```yaml
---
mode: feature        # 恒为 feature(本 skill 只处理已有项目里的行动)
wave: 0              # 0 = confirm-list 独立波;1+ = 正式题波
stage: confirm
created: YYYY-MM-DD
status: pending | answered | processed | archived
---
```

status 流转:`pending`(已生成待作答)→ `answered`(用户答完待解析)→ `processed`(已落盘待归档)→ `archived`(已归档)。

## 文件结构

每次确认 = **W00(confirm-list,独立问卷)+ W01+(正式题波,兜底)** 两类文件,**分开交付**。**预期形态:多数确认只有 W00 + 小波直接问,W01 文件很少出现**——preview 为主、正式题波为兜底,不为出问卷而出题(反形式主义)。

### W00 · confirm-list 问卷模板(`confirm-<slug>-w00.md`)

```markdown
---
mode: feature
wave: 0
stage: confirm
created: YYYY-MM-DD
status: pending
---

# 问卷 confirm W00 · 细节确认清单(AI 汇报理解,人核对)

> **本波是细节确认清单**(独立 wave 0):把 AI 对本次行动细节的理解逐条列出,人只做「对/不对」核对。
>
> **作答规则**:
> - 勾 `[x]` = **理解正确**(按该理解执行)
> - 留空 `[ ]` = **理解有误或要改** → 该要点转正式题深究(或小波直接问)
> - 本波**不用 🤔**(对/不对二选一,无中间态);「大体对但要改一两处」→ 留空,转正式题时在深究题里给正确值
>
> 来源标注于〔〕:**〔推断〕= AI 填的,重点核对**;〔用户原话 / 代码 / 文档〕= 有据。

## 细节确认清单

### 目标
- [ ] **1 <细节点>**:<AI 的理解> 〔来源〕

### 输入
- [ ] **2 ……**

### 输出
### 约束
### 边界
### 依赖
(六要素按行动实情裁剪;空要素整节省略)

## 补充声明

<任何想补充的话……没有就留空。agent 处理时必读>
```

### W01+ · 正式题问卷模板(`confirm-<slug>-w01.md` 起)

```markdown
---
mode: feature
wave: 1
stage: confirm
created: YYYY-MM-DD
status: pending
---

# 问卷 confirm W<NN> · <一句话主题>

> **与 W00 的关系**:W00(confirm-list)中**留空(理解有误/要改)**的要点,处理后会作为正式题**追加到本波尾部**逐个深究(≤4 题则不生成文件,小波直接问)。本波另列**开放型确认项**(多选/方向型,不适合 W00 的对/不对)。

> **填写规则**:
> 1. 每题勾选 `[x]`;默认单选,标「(多选)」可勾多个,选项数不限
> 2. ★ = 推荐选项,附推荐理由;**选项排序 = 非推荐在前 → 逃生舱倒数第二 → 推荐最后**(规则 14)
> 3. 每题末尾 🤔 是逃生舱:勾了 = 我定不了 → agent 走降风险协议,绝不重问
> 4. 选项都不合适 → 在 ✍️ 自定义 后自由书写
> 5. 标「条件:Qn 选 X 才答」的是内联浅分支,条件不满足直接跳过
> 6. **预勾选 = opt-in 开关**(默认关):你启动本 skill 时明确说「预勾选」才预勾推荐选项,否则全部 `[ ]`(规则 15;confirm-list 无选项,不适用)

## Q1. <问题文本>   [落盘: <目标文档#章节>]

<可选:出题依据——提取发现的矛盾/盲点,一两行,附出处;涉代码事实/外部依赖的题必须附核实证据>

- [ ] A. <选项>  —— <代价/风险>
- [ ] B. <选项>  —— <定位/利弊>
- [ ] 🤔 我定不了 → 推迟/降风险
- [ ] C. <选项>  ★推荐 —— <理由>
- ✍️ 自定义: __________

---

## 补充声明

<任何想补充的话:新需求、格式反馈、范围调整、临时想到的风险……没有就留空。agent 处理时必读>
```

## 规则细则

1. **选项数不限**,但每个选项必须带一句定位、利弊或代价,不能只给名词。
2. **★推荐**:agent 有明确倾向时标一个(只能标一个),必须附理由;没有倾向就不标,不硬凑。
3. **🤔 逃生舱**:**W01+ 正式题每题必有**,固定在选项末尾、✍️自定义之前。**W00 confirm-list 不用 🤔**(对/不对二选一,无中间态)。对话速答中出现「不知道/不确定/你决定/推迟/看你」等,视同勾了逃生舱。
4. **✍️自定义**:W01+ 每题必有。对话速答的自定义内容逐字转写到该行,不润色、不概括。
5. **内联浅分支限 1 层**(允许 `Qn.m`,禁止 `Qn.m.k`);更深的分支不在本问卷展开,记入处理报告的「下一波候选」。
6. **[落盘:] 提示**:W01+ 每题必标,取值见 PROCESSING-RULES.md 的落盘映射表。出题时标错,处理时可纠正,但必须在处理报告中说明。
7. **出题依据**:凡因提取发现(代码矛盾、术语冲突、上轮答案引出)而出的题,必须在题干下注明依据和出处;**涉代码事实/外部依赖的条目与题,必须附核实证据(命令/原文出处),核实不了的标「未验证假设」**(本 skill 铁律 2)。
8. **题量**:正式题波每波 10–15 题;超量拆子波。**confirm-list 不受此限**(要点数建议 5–20)。
9. **多选标记**:默认单选;确实可同时成立多个答案的题,在题干尾部标「(多选)」。
10. **Markdown 排版**:数值范围用 en dash(`–`),禁止半角 `~` 表示范围;遵循全局排版规范。
11. **安全**:问卷中禁止出现密钥、真实隐私数据、未公开商业机密;涉及安全关键操作的题,在出题依据中标注「需人逐行审查」。
12. **补充声明区**:W00 与 W01+ 末尾均固定设「补充声明」自由书写区。agent 处理问卷时必读,内容按类型处理:新需求 → 下一波或修订理解;答案补遗 → 按映射落盘;格式反馈 → 修订本规范;**用户先验结论 → 列为待验证假设,分析/处理中显式检验,不预设为结论(防确认沦为给用户先验背书),处理报告标注**。所有去向写入处理报告。
13. **confirm-list(每次确认独立 W00)**:先生成独立 `confirm-<slug>-w00.md`,**不与 W01 同文件**。一要点一行 = 细节点 + AI 的理解 + 来源,要点数建议 5–20,按隐式骨架六要素(目标/输入/输出/约束/边界/依赖)组织。每条 `[ ]`:勾 `[x]` = 理解正确(按该理解执行);留空 = 理解有误或要改(转 W01 深究或小波直接问)。**W00 不用 🤔**;底部补充声明栏保留。W01 正式题 = W00 留空要点的深究 + 不适合对/不对的开放型确认项;已在 W00 确认正确的细节不重复出题,处理报告标注来源 = W00 确认。
14. **选项级排序(默认行为,2026-08-03 起)**:W01+ 正式题每题选项顺序 = **非推荐选项在前 → 🤔 逃生舱倒数第二 → ★推荐选项最后**(利用线性阅读,推荐项是用户扫到最后才看到的「答案」)。★推荐仍只标一个、附理由;排序不依赖预勾开关。W00 confirm-list 无选项列表,不适用。
15. **预勾选 = opt-in 开关(默认关,2026-08-03 起)**:仅当用户启动本 skill 时**明确说「预勾选」**才预勾推荐选项(标 `[x]`,仅 W01+ 适用);未启用时全部选项保持 `[ ]`。开关开启时配套:**单向门题(发布/删除/花钱/脱敏等不可逆)仍不预勾,强制必答**;设防见 PROCESSING-RULES.md「预勾设防」。
