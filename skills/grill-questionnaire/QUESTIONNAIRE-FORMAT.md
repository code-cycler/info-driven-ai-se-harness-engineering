# 问卷格式规范(design-questionnaire 引擎 · 复用件)

> ⚠️ 本文件是 design-questionnaire 引擎的副本(2026-07-24 复制)。design-Q 为 canonical;另有 retro-questionnaire、grill-questionnaire 两份副本,共三份。修改需考量三方同步,漂移需声明(见三处 DESIGN.md)。
> 本 skill 的问卷 frontmatter `stage` 固定取 `grill`(引擎模板里的 vision|hld|lld 是 design-Q 的词汇,本 skill 不用)。

> 本文件与 [PROCESSING-RULES.md](./PROCESSING-RULES.md) 共同构成问卷引擎。后续 skill(如 retro-questionnaire)复用这两个文件,只换自己的骨架模板。

## 文件约定

- 活动问卷目录:`harness/questionnaires/`(懒创建,首次生成问卷时才建)
- 命名:
  - init 模式:`<stage>-w<NN>.md`(stage ∈ `vision` | `hld` | `lld`;NN 从 01 递增)
  - feature 模式:`feature-<slug>-<stage>-w<NN>.md`(slug 为功能短名,kebab-case)
  - 同 wave 超题量拆子波:`<stage>-w<NN>a.md`、`<stage>-w<NN>b.md`
- 归档:处理完毕移入 `harness/questionnaires/archive/`,文件名不变,只移不删

## frontmatter(必填)

```yaml
---
mode: init | feature
wave: 1
stage: vision | hld | lld
created: YYYY-MM-DD
status: pending | answered | processed | archived
---
```

status 流转:`pending`(已生成待作答)→ `answered`(用户答完待解析)→ `processed`(已落盘待归档)→ `archived`(已归档)。

## 文件结构(模板)

```markdown
---
(frontmatter)
---

# 问卷 <stage> W<NN> · <一句话主题>

> 填写规则:
> 1. 每题勾选 `[x]`;默认单选,标「(多选)」可勾多个,选项数不限
> 2. ★ = 推荐选项,附推荐理由;**选项排序 = 非推荐在前 → 逃生舱倒数第二 → 推荐最后**(规则 14)
> 3. 每题末尾 🤔 是逃生舱:勾了 = 我定不了 → agent 走降风险协议,绝不重问
> 4. 选项都不合适 → 在 ✍️ 自定义 后自由书写
> 5. 标「条件:Qn 选 X 才答」的是内联浅分支,条件不满足直接跳过
> 6. **预勾选 = opt-in 开关**(默认关):你启动本 skill 时明确说「预勾选」才预勾推荐选项,否则全部 `[ ]`(规则 15)

## Q1. <问题文本>   [落盘: <目标文档#章节>]

<可选:出题依据——探索发现的事实/矛盾/盲点,一两行,附出处>

- [ ] A. <选项>  ★推荐 —— <理由>
- [ ] B. <选项>  —— <代价/风险>
- [ ] C. <选项>
- [ ] 🤔 我定不了 → 推迟/降风险
- ✍️ 自定义: __________

### Q1.1 (条件: Q1 选 B 才答) <浅分支子问题>   [落盘: <目标文档#章节>]

- [ ] ……
- [ ] 🤔 我定不了 → 推迟/降风险
- ✍️ 自定义: __________

---

## 补充声明

<任何想补充的话:新需求、格式反馈、范围调整、临时想到的风险……没有就留空。agent 处理时必读>
```

## 规则细则

1. **选项数不限**,但每个选项必须带一句定位、利弊或代价,不能只给名词。
2. **★推荐**:agent 有明确倾向时标一个(只能标一个),必须附理由;没有倾向就不标,不硬凑。
3. **🤔 逃生舱**:每题必有,固定在选项末尾、✍️自定义之前。对话速答中出现「不知道/不确定/你决定/推迟/看你」等,视同勾了逃生舱。
4. **✍️自定义**:每题必有,紧跟 🤔 逃生舱之后。对话速答的自定义内容逐字转写到该行,不润色、不概括。**出题后自检**:🤔 逃生舱数 必须等于 ✍️ 自定义行数(等于题数)——`grep -c '🤔 我定不了'` 与 `grep -c '✍️ 自定义: ____'` 应相等;不等则问卷残缺,补齐再交付(dogfood 教训:曾两次遗漏 ✍️ 自定义行)。
5. **内联浅分支限 1 层**(允许 `Qn.m`,禁止 `Qn.m.k`);更深的分支不在本问卷展开,记入处理报告的「下一波候选」。
6. **[落盘:] 提示**:每题必标,取值见 PROCESSING-RULES.md 的落盘映射表。出题时标错,处理时可纠正,但必须在处理报告中说明。
7. **出题依据**:凡因探索发现(代码矛盾、术语冲突、上轮答案引出)而出的题,必须在题干下注明依据和出处,让用户能判断这题为什么存在。
8. **题量**:每波上限 10 题(2026-08-08 用户裁决收紧,原 10–15)。阶段骨架未覆盖项优先于动态盲点;超量拆子波。
9. **多选标记**:默认单选;确实可同时成立多个答案的题,在题干尾部标「(多选)」。
10. **Markdown 排版**:数值范围用 en dash(`–`),禁止半角 `~` 表示范围;遵循全局排版规范。
11. **安全**:问卷中禁止出现密钥、真实隐私数据、未公开商业机密(方法论 §8.8);涉及安全关键设计的题,在出题依据中标注「需人逐行审查」。
12. **补充声明区**:每份问卷末尾固定设「补充声明」自由书写区。agent 处理问卷时必读,内容按类型处理:新需求 → 下一波或修订规格;答案补遗 → 按映射落盘;格式反馈 → 修订本规范。所有去向写入处理报告。
13. **选项级排序(默认行为,2026-08-03 起)**:每题选项顺序 = **非推荐选项在前 → 🤔 逃生舱倒数第二 → ★推荐选项最后**(利用线性阅读,推荐项是用户扫到最后才看到的「答案」)。★推荐仍只标一个、附理由;排序不依赖预勾开关。
14. **预勾选 = opt-in 开关(默认关,2026-08-03 起)**:仅当用户启动本 skill 时**明确说「预勾选」**才预勾推荐选项(标 `[x]`);未启用时全部选项保持 `[ ]`。开关开启时配套:**单向门题(发布/删除/花钱/脱敏等不可逆)仍不预勾,强制必答**;设防见 PROCESSING-RULES.md「预勾设防」。
