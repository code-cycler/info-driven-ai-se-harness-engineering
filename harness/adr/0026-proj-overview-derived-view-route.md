# ADR-0026: proj-overview 视图派生路线(人读项目掌控视图)

- 状态:accepted
- 日期:2026-09-23
- 来源:grill-human-project-view-w01 Q8(压测裁决;先例 = ADR-0011 可逆决策立 ADR)
- 修订注记(2026-09-26,版本内修订,grill-proj-overview-v2 W01):受众扩展为**任何开发者**(原 = 项目掌控者本人单一受众);行数硬上限 ≤250 **废除**(替代 = 派生性质即约束——行数随源文件面线性增长,分型自检:事实段溯源/结构段对规格);新增**治理文件 summary 职责**(ADR/OD 全量每条一行,派生转述不承接活职责);产物定位升级为「**认读第一入口**」(人重载上下文从此开始;CONTEXT 词条)。路线本体(不删文件、只读派生、宽松漂移、失忆测试锚)不变;v2 设计套 [harness/design/proj-overview-v2/](../design/proj-overview-v2/)。产物落点由 `harness/` 改**项目根** `PROJECT-OVERVIEW.md`(2026-09-26 同日再修订:认读第一入口可发现性优先,与 README/CLAUDE/TODO 同级;HARNESS-RULES §六落点同步修订)。

## 背景

哲学 v7 挑战报告挑战三(元系统膨胀):为单人设计的方法论长出治理部门——25 ADR / 28 OD / 238 md 中「哪份是权威」成为最大信息断层。同时用户实践感受:harness 文件承担**人读与 AI 读双职责**——对 AI 是重建上下文的保障(须严谨详细),对人却是「太多太长」,人的上下文与注意力不足,跨时空切入时掌控难。

需要裁决:如何回应「文件太多人掌控难」——削减/合并文件,还是别的路线。

## 决策

**视图派生路线**:新增横切工具型 skill proj-overview(家族第 9 个),为宿主项目生成单份**只读派生**的人读项目掌控视图(`harness/PROJECT-OVERVIEW.md`,md + mermaid,线性五段 + BFS 层次分解图 / DFS 功能逻辑链):

1. **不删并既有文件、不新增权威源、不参与规范优先级裁决**——只加一个派生视图层;
2. **设计取向**(grill Q6 裁决降格,非可测判据):「减的负荷 > 加的负荷」——以降低人的检索/整合成本对冲文件数量不变;
3. 验收锚 = **失忆测试**(隔 ≥3 天只读视图 ≤15 分钟答三问:主线 / 关键决策所在 / 下一步;人判非 AI 自评);
4. 宽松漂移治理(不进校验脚本、手动重生成)——防本机制自身退化为第四个提交前检查脚本。

完整规格见设计套 [harness/design/human-project-view/](../design/human-project-view/)(L0 目标层 / L1 契约层 / L2 构建层)。

## 被否决项

- **文件削减/合并路线**:治理文件各有职责与既有引用,削减引发引用断链与信息丢失;且「哪份该删」本身是高判断成本决策。
- **并入 doctor-harness 或其他既有 skill**:doctor-harness 域 = 布局规则治理,产物生成与其职责正交;设计期闸门已裁决独立 skill。
- **HTML 双格式首期交付**:破坏 Git diff 语义,违反 YAGNI;实测链路已留存,重访触发 = md 版失忆测试通过且多环境渲染痛点实证(grill Q1)。
- **强同步漂移治理(hash 对账进提交前检查)**:元成本显著上升,与回应元系统膨胀初衷相悖;降为文件头三件套自声明 + 人自判新鲜度。

## 后果

- (+) 人的掌控成本与文件数量解耦;「人读/AI 读职责分野」在 skill 层机制化(canonical 论述缓行,独立审查另走)。
- (+) 可逆:skill 可退役、产物可删,均为双向门。
- (−) 视图有过期误导风险——对策 = 文件头三件套 + 图节点带源链接 + 禁按过期图做单向门决策。
- (−) skill 本身是元系统新增件——对策 = 本体极简(SKILL.md < 100 行、无引擎副本)+ 视图总长 ≤ 250 行硬约束。
