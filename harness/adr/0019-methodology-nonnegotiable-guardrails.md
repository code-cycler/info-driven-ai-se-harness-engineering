# ADR-0019: 方法论不可裁剪治理核心

- 状态:accepted(2026-08-14,grill-Q philosophy-v7 W01 Q9)
- 决策日期:2026-08-14

## 背景

哲学 v7 的元原则允许按项目、场景和工具调整流程,同时在分工、黑盒治理和 WAI/WAD 边界中散落了若干最低要求。若没有一处明确的不可裁剪核心,「按项目调整」可能被解释成静默取消人审、留痕或独立验证。

## 决策

以下四项是方法论的不可裁剪治理核心:

1. **判断性决策与最终确认由人承担**:AI 可以提供信息、分析和受约束的执行,不能自主决定目标、风险取舍、验收是否符合意图。

> **澄清注记(2026-08-18,grill-Q first-principles W01 Q3)**:第 1 条含两层——**责任恒定于人**(伦理层:目标、风险取舍、验收与签字的**归属**不可下放、不可裁剪,恒定)+ **执行判断的质量门槛可随工具调整**(经验层:哪些执行类判断够格下放,由 delegate pilot 数据决定;`mode: full` 等演进属经验层,不触碰责任层)。本注记不改决策本身,消除与 delegate 演进([OD-13](../../docs/OPEN-DECISIONS.md))的表面冲突。
2. **单向门先停并留痕**:涉及删除、发布、付费、对外传播、数据外泄或等价不可逆风险时,先暂停并由人确认,过程与结果可追溯。
3. **L3 必须有独立验证**:AI 自写 oracle、用户可玩产物和单向门操作分别需要人审测试/试玩/确认或独立客观裁决;AI 自评不能单独作为通过依据。
4. **冲突不得静默覆盖**:文档、执行与现实冲突时,必须保留事实与副作用、标记影响范围并进入恢复或重访路径,不得用覆盖文件或静默重试掩盖。

除上述核心外,流程、记录粒度、采样频率和工具选择可按风险与项目成本裁剪;裁剪必须记录理由、当前状态和重访条件。

## 替代方案(被否决)

- **全部原则自由裁剪**:成本最低,但失去方法论最低安全边界。
- **全部流程一律强制**:边界最硬,但与个人开发者的成本目标和 WAI/WAD 弹性边界冲突。

## 后果

- (+) 为「按项目调整」提供不可被静默取消的底线。
- (+) 可作为方法不变量与验证卡的首批三个主题来源:判断权、L3 独立验证、单向门/冲突恢复。
- (−) 不可裁剪核心仍需要在哲学正文、方法论文件和 skill 规格中完成交叉引用与验证卡映射。
- (−) 「等价不可逆风险」需要按采用项目具体判定,不能由本 ADR 自动穷举全部场景。
