# retro 骨架模板(retro-questionnaire)

> 复盘问卷的固定结构:方法论四节 + Action Items(hld-W1-Q2 选 A)。
> 出题时按五源读取的结果具体化,不得照抄题干;反思题选项 = 「常见原因假设清单」(VISION 决策),真实答案以 ✍️ 自定义为准。

## 问卷结构

### 0. Action Items 回顾(有上一份 retro 时必有)

列出上一份 retro 的 Action Items,逐项一题:「该项是否已完成?」选项:已完成 / 部分完成 / 未开始 / 已失效 + ✍️ 自定义。未修项自动进入本次 Action Items 候选。

### 1. 进展顺利(What went well)

出题方向:本阶段什么做对了、值得保留?按领域分题(流程 / 工具 / 设计 / 协作),多选候选 + 自定义。

### 2. 出问题与原因假设(What went wrong)

出题方向:本阶段出了什么问题?每个问题一题,选项 = 常见原因假设清单:

- 需求 / 构想不清(没想清楚就动手)
- 设计缺陷(设计文档本身错了或漏了)
- 实现偏离设计(实现走偏,设计文档未更新)
- 验证不足(测试 / Review 没拦住)
- 上下文 / 信息丢失(决策没沉淀,重复讨论)
- 外部依赖 / 环境变化
- 🤔 我定不了 → 推迟/降风险
- ✍️ 自定义(真实原因以此为准)

### 3. 架构偏离

出题方向:实现与设计文档(HLD / LLD)哪里不一致?逐项列出(事实收集,附出处);每项一问:这是「设计不完善」还是「实现发现了更好的方式」?(选项 + 自定义;**只记录定性,后续动作由人发起**)

### 4. 学到什么

出题方向:本次开发获得、对未来可复用的经验。开放题为主,可给候选方向(工具 / 流程 / 方法论 / 领域认知)。

### 5. Action Items(固定节)

从 2、3 节提炼行动项,格式:**问题 → 行动 → 核验时机**。落盘:retro 文档 Action Items 节 + 宿主项目 `TODO.md`。

## 落盘契约

- retro 文档:宿主项目 `docs/retro/<主题>_vN.md`(_vN 递增,禁 final/new/copy)
- 行动项:宿主项目 `TODO.md`
- 问卷归档:宿主项目 `harness/questionnaires/archive/`(尾部附处理报告摘要)
