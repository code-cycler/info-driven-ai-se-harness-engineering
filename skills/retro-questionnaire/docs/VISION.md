# retro-questionnaire · VISION

> 2026-07-23 由 design-questionnaire 的 vision W1 问卷落盘生成。
> 问卷归档:[docs/questionnaires/archive/vision-w01.md](./questionnaires/archive/vision-w01.md)

## 动机

一句话念头(用户原话):「再做一个 retro skill,复用同一套逻辑」。

推导:复盘是「信息不丢失」的最后一道防线,但又是最常被跳过的一步(方法论§常见误区 6)。design-questionnaire 的问卷引擎已建,把复盘也问卷化——让复盘变成有触发、有结构、有落盘的固定动作。

## 目标

核心目标:**防省略**(W1-Q1 选 A)。把复盘从「靠自觉」变为「有触发、有结构、有落盘」。挖深度、提效率是次要目标,不是本 skill 的主要矛盾。

## 范围

**做**:

- 阶段末复盘:每个 LLD 阶段 DoD 核验后触发(W1-Q2 选 A)
- agent 检测到阶段 DoD 核验通过后主动提议发起,是否复盘由人确认(W1-Q2.1 选 A)
- 支持手动触发,随时及时记录,类似 memory(W1-Q2 ✍️自定义)
- 反思题与决策题同构:选择题 + 🤔 + ✍️;反思题的选项 = 「常见原因假设清单」供快速勾选,真实答案走自定义(W1-Q3 选 A)

**不做**(明确排除):

- 不自动修改设计文档;复盘只记录偏离,更新设计文档由人发起(W1-Q4 选 A、W1-Q5 选 A)

> 注:W1-Q4 的 B(不对人评价)、C(不做度量统计)、D(不跨项目汇总)未勾选,按规则解释为「未排除」。处理报告已提示,用户未在闸门前提议修正则维持此解释。

## 核心场景

1. LLD 阶段 DoD 核验通过 → agent 主动提议复盘 → 人确认
2. 生成 retro 问卷(复用 design-questionnaire 引擎,换 retro 骨架)
3. 用户作答(编辑文件或对话速答,文件为唯一事实源)
4. 落盘 `docs/retro/<主题>_vN.md`(W1-Q8 选 A,沿用项目版本命名),已用问卷归档
5. 用户可随时手动触发,及时记录
6. 复盘产出的行动项写入 `<项目根>/TODO.md`(格式:问题 → 行动 → 核验时机);agent 在生成新问卷、阶段闸门、DoD 核验、新会话恢复时必读 TODO.md(W2-Q1 ✍️自定义)

**架构偏离处理**:仅记录在 retro 文档「架构偏离」节(是设计不完善还是实现发现了更好的方式);后续动作(更新设计文档 / 新 ADR)由人发起(W1-Q5 选 A)。

## 验收标准

用一次真实阶段复盘走通闭环:触发 → 生成 retro 问卷 → 作答 → 产出 `docs/retro/` 文档 → 归档问卷(W1-Q6 选 A)。

## 风险与约束

- **复盘形式主义**(填空套话,一年后没人想读)——头号风险(W1-Q7 选 A)。缓解:反思题选项用假设清单启发思考,不诱导套话。
- **复盘发现的问题没有及时修正**(W1-Q7 ✍️自定义)。缓解:行动项落 `<项目根>/TODO.md`,agent 四个时机必读(W2-Q1 ✍️自定义);核验结果在下一份 retro 文档「Action Items 回顾」节体现。

## 决策记录

本波无逃生舱,无 OPEN-DECISIONS 条目。Q1–Q8 决策均可逆(双向门),未达 ADR 门槛,记录于本文档。
