<what-to-do>

把「动手前凭感觉确认几句」改为「多波次问卷的细节确认」:行动前把 AI 提取的行动细节与理解写成一份**细节确认清单(confirm-list)**问卷,用户离线核对(勾 = 理解对、留空 = 理解错或要改),留空项转正式题深究或按小波阈值直接问,确认结果即时落盘留痕。**这是确认式问卷,不是生成式设计问卷**——AI 汇报理解,人核对;不是 AI 提议方案,人采纳。

## 铁律(不可违反)

1. **AI 不替人决策** — 清单提供 AI 的理解与 ★推荐,确认与选择永远是人的。agent 的角色是提取、验证、出题、落盘。
2. **先核实再列清单(环境现实验证)** — 凡清单/题目涉及**代码事实或外部依赖**(库、工具链、路径、版本、现有实现行为),列出前必须核实原文或实测,证据写入出题依据;无法核实的在条目中显式标注「未验证假设」。**用户确认只能对齐用户脑中的背景;AI 自己误读了现实,用户是看不出来的**——确认"AI 的误读 + 用户的追认"等于给幻觉背书。
3. **写操作默认确认** — 非正式行动的写操作,行动前默认要走本确认;**除非项目显式声明该操作继承 delegate 白名单**(此时按 delegation.md 豁免)。确认优先于下放:delegate 白名单不自动豁免本 skill,豁免必须显式声明。
4. **逃生舱绝不重问** — 用户勾了 🤔(或对话速答中表达「不确定/你决定」),走降风险协议(见 [PROCESSING-RULES.md](./PROCESSING-RULES.md)),不得换个说法再逼问同一题。
5. **即时沉淀,不批处理** — 每波处理完,确认结果立即归档留痕;满足 ADR 三条件(难逆转+会困惑+真权衡)的决策立即升格 `docs/adr/`,单向门/重大风险升格 `docs/OPEN-DECISIONS.md`,术语冲突升格 `CONTEXT.md`,不攒到行动末。
6. **原始信息不丢失** — 问卷文件是唯一事实源;对话速答逐字转写进问卷文件;已处理问卷归档(只移不删)。
7. **不越界做设计** — 确认中发现行动实为 feature 级(值得 feature 记录、改方向、多文件结构性变更),不顺势在本 skill 里展开设计——提醒用户转专用 skill(见第 5 步),本 skill 只留确认记录。

## 主流程

### 0. 触发与定界

- **触发**:非正式行动的写操作前默认触发(铁律 3);用户显式触发(「对齐一下」「确认细节」「preflight」)亦可。
- **定界(先做,防误用)**:判断行动是否 feature 级——值得 feature 记录、改方向、多文件结构性变更、需要设计先行。是 → 不启动本 skill,提醒转 design-Q(需设计)/ grill-Q(有工件要压测)/ long-running(跨会话实现)。否 → 继续。
- **delegate 豁免检查**:读 `<项目根>/delegation.md`(若存在);用户或项目**显式声明**本操作继承白名单 → 免确认直接执行并记 delegation-log;无显式声明 → 默认确认。

### 1. 提取与核实

- 提取**行动细节清单**:按隐式骨架六要素——**目标 / 输入 / 输出 / 约束 / 边界 / 依赖**——把 AI 对本次行动的理解逐条列出。每条 = 细节点 + AI 的理解 + 来源(用户原话 / 代码 / 文档 / 推断)。推断来源必须标出——「推断」是幻觉的合法入口,用户要能看到哪些是事实、哪些是 AI 填的。
- **核实(铁律 2)**:凡涉代码事实(「这个函数现在返回 X」)与外部依赖(「环境里装了 Y 版本」)的条目,核实原文或实测后再列入;证据写入条目依据;核实不了的标「未验证假设」。
- **动态盲点**:提取中发现的矛盾(用户说的 vs 代码做的)、未定义边界,直接成为清单条目或正式题候选。

- **实测与调研前置(标准流程,2026-08-03 起)**:提出问卷前,完成「调研现状 → 不假设 → 多实测 → 多获取信息 → 及时保存」闭环——
  1. **调研现状**:读 CLAUDE.md / CONTEXT / ADR / OPEN-DECISIONS / TODO / 相关代码区,不凭记忆出题;
  2. **不假设**:凡要引用进问卷的事实,不凭转述/记忆,必须核实原文或实测;
  3. **多实测**:不只查存在(`--version`/`brew list`),须实际跑通(编译链接 / 运行 / 调用级);证据(命令 + 输出 + 最小程序)记入出题依据;
  4. **多获取信息**:实测中发现的额外信息(版本差异、隐藏依赖、行为细节)一并记录;
  5. **及时保存信息**:证据与发现**立即**写入问卷出题依据 / 处理文件,不攒到出题后;无法实测的显式标「未验证假设」并放问卷最前(衔接问题级排序)。

### 2. 生成问卷

- **confirm-list(默认首波,独立 wave 0)**:生成 `confirm-<slug>-w00.md`——细节确认清单,一要点一行 = 细节点 + AI 的理解 + 来源。每条 `[ ]`:**勾 `[x]` = 理解正确**(按该理解执行)、**留空 = 理解有误或要改**(转正式题深究,或按小波阈值直接问)。W00 **不用 🤔**(对/不对二选一,无中间态);底部「补充声明」栏保留。格式见 [QUESTIONNAIRE-FORMAT.md](./QUESTIONNAIRE-FORMAT.md)。
- **正式题波(W01+,兜底)**:**preview 为主、正式题波为兜底是本 skill 的预期形态**——多数确认流程 = W00 清单 + 小波直接问,W01 问卷文件很少出现;不为「用上问卷文件」而硬出题(反形式主义)。W01 = W00 留空要点的深究 + 不适合 yes/no 的开放型确认项。
- **小波阈值**:若正式题数 ≤ 4,不生成问卷文件,改用 AskUserQuestion 直接提问(仍给 ★推荐与 🤔 逃生舱);问答与处理摘要逐字记入处理报告,追加到最近一份归档问卷尾部。
- 题量:正式题波每波 10–15 题,超出拆子波;confirm-list 不受此限(要点数建议 5–20,行动轻量故从简)。

### 3. 用户作答

- 默认:用户直接编辑问卷文件(`[ ]` → `[x]`、填 ✍️ 自定义行),保存后通知 agent。
- 也接受:对话速答,agent **逐字**转写进问卷文件,然后以文件为准解析。
- 用户宣布「答完了」之前不解析。

### 4. 处理与落盘

- 按 [PROCESSING-RULES.md](./PROCESSING-RULES.md) 逐题解析(含异常:单选多勾、必答未答、条件题误答)。
- 落盘(本波处理完即刻):
  - **确认结果** → 问卷归档为唯一常规留痕(`docs/questionnaires/archive/`,只移不删);后续会话可重新加载。
  - **满足 ADR 三条件的决策** → `docs/adr/`(确认中揪出的决策照常记录,不因「非正式行动」而免记)。
  - **单向门/重大风险/存疑假设** → `docs/OPEN-DECISIONS.md`(必填重访触发条件)。
  - **术语冲突** → `CONTEXT.md`。
- 🤔 逃生舱 → 降风险协议,绝不重问。
- 输出**处理报告**(对话内,格式见 PROCESSING-RULES.md):每条去向、新增/更新文件、异常处理、逃生舱处置、confirm-list 统计(确认正确 X / 留空纠正 Y)、覆盖度(隐式骨架六要素确认情况)。

### 5. 循环与终止

- 判据「**再无可确认的细节**」:隐式骨架六要素(目标/输入/输出/约束/边界/依赖)全部确认过 + 动态盲点清零 + 逃生舱项已全部进 OPEN-DECISIONS。
  - 还有 → wave+1,回第 2 步。
  - 没了 → 出示覆盖清单(六要素 × 确认状态),**然后才动手**。
- **升级转出**:确认中(或确认后动手前)发现行动实为 feature 级 → 立即提醒用户转专用 skill(design-Q / grill-Q / long-running),本 skill 的确认记录作为输入留档,不替代设计流程。
- 收尾:确认完成 → 按确认的理解执行行动;行动完成后把处理报告摘要追加进归档问卷尾部(单文件可回溯)。

## 与家族的分工

| | action-questionnaire | design-questionnaire | grill-questionnaire | grill / grill-with-docs | delegate |
|---|---|---|---|---|---|
| 场景 | **非正式行动前**的细节确认(对齐防幻觉) | 启动初始化、功能设计(生成式) | 已有工件的对抗压测 | 实现期单点二义性(一问一答) | 纯执行决策下放(横切) |
| 交互 | confirm-list 为主 + 小波直接问(阈值 ≤4),正式题波兜底 | 多波次问卷(preview + 正式题) | 多波次问卷(D1–D8) | 一问一答,逐轮等待 | 白名单内不问人 |
| 落盘 | 归档问卷 + 三条件升格 ADR/OD/CONTEXT | VISION/HLD/LLD/ADR/OD/CONTEXT | 处理报告 + ADR/OD/CONTEXT | CONTEXT/ADR/OD | delegation.md + log |
| 边界 | 行动升级到 feature 级 → 提醒转专用 skill | feature 级设计 | 有工件要挑战 | 单点深钻 | **显式声明继承白名单才豁免本确认** |

**衔接**:本 skill 是「轻量前奏」,不是设计流程的替代品。design-Q 收尾的设计进入实现前,可用本 skill 对齐实现动作细节;grill-Q / retro-Q 处理的行动项落地前,亦可用本 skill 确认。发现 feature 级行动 → 转出(第 5 步)。

## 已知限制

- **只对齐 (a) 类幻觉的一半**:用户确认对齐的是「用户脑中的背景」;AI 误读现实那半靠铁律 2(先核实再列清单)兜,但核实深度有限——涉复杂代码行为的行动,确认后仍应小步验证。
- **不替代设计与压测**:本 skill 无内容骨架、无对抗维度,发现的问题深度不及 grill-Q;feature 级行动必须转出。
