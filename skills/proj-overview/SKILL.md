为「人读」生成一页项目掌控视图。harness 文件面向 AI 重建上下文（严谨详细），本产物面向人（认知友好）——只读派生，设计取向「减的负荷 > 加的负荷」。

## 定位与边界

- 横切工具型：不进 5 环节闭环主路径；纯生成，无问卷无 AskUserQuestion。
- 产物 = 单份只读派生视图：不新增权威源、不参与规范优先级裁决、**以源文件为准**。
- 不做五文件既有职责：AI 会话入口（CLAUDE.md）/ 对外宣传（README）/ 变更记录（CHANGELOG）/ 行动追踪（TODO）/ 状态史（STATUS-LOG）。
- 禁止按过期视图做单向门决策（发布/删除/花钱/脱敏前必回源文件核对）。

## 主流程四步

1. **扫描（分级读取三档，禁全仓深读）**：结构类全读（README / CLAUDE.md / 目录树）；治理类头读（CONTEXT 节标题 / OD 条目头 / ADR 标题行 / 设计套索引）；关键 N 份选读（承载当前主线的文件，从状态追踪文件与近期变更反推）。
2. **抽取**：节点两类（功能/结构节点、信息/工件节点）；边三类（包含、依赖、流转·触发）。当前状态快照 = 项目状态追踪文件头部（遵循本方法论时 = TODO.md 头部）**直接引用转述，AI 不新增判断**；无此惯例的项目以 git 近况为准并在快照段标注数据源；头部与 git 近况明显不一致 → 提示人先更新再生成，AI 不代写。
3. **组织**：五段固定序 ① 项目定位一句话 → ② 结构全景（BFS 总图 + 区块索引表）→ ③ 决策脉络（关键决策时间线）→ ④ 当前状态快照 → ⑤ DFS 深链视图。
4. **渲染**：md + mermaid 代码块；图内用短名/编号，链接统一放图旁索引表（markdown 相对链接，文件级为主、关键链到「文件#节」锚点）。

## 输出规格（硬约束）

- 落点 `harness/PROJECT-OVERVIEW.md`；手动触发、覆盖式重生成（git 历史即版本，不做 `_vN` 递增）。
- 文件头三件套：生成时间戳 + 信息源清单（路径 + 每文件一行摘要）+「以源文件为准，派生视图」声明。
- 总长 ≤ 250 行（超限即精简：详略分级 / 链接外移）；单段目标 ≤ 15 行。
- **BFS 一张层次分解图**：项目根 → 各层次 → 每层次下属功能，逐层展开到功能粒度（功能之下交给 DFS 与索引表）；≤ 30 节点，超限按层聚合（聚合优先保每层功能完整）；分层依据以注记写在「结构全景」段。
- **DFS 每功能一条逻辑链**：功能 → 内部逻辑/子功能 → 依赖 → 落点工件；关键功能（承载当前主线/高风险）全链展开，其余功能一行短链 + 索引表；每图 ≤ 30 节点，图数 ≥ 2 且 ≤ 12。
- 漂移宽松：不进校验脚本、无强制同步义务；新鲜度靠文件头三件套自声明。

## 人因设计原则

- 信息分层：披露顺序 = 概览 → 结构 → 链路 → 状态（先全景后细节）。
- 渐进披露三级：概览层无链接 → 结构层索引表 → 链路层「文件#节」锚点。
- 图规模 ≤ 30 节点/图；线性认知顺序（五段固定序不重排）。
- 学科锚：认知负荷、情境意识（引 CONTEXT 既有定义，不新造术语）。

## 文风规范

- 禁令：比喻性代称（「定海神针」类）、文学修辞、情绪化形容。
- 术语表（系统工程通用交集，不引用单一标准）：模块 / 接口 / 依赖 / 基线 / 追溯性 / 验证 / 配置项 / 职责 / 边界 / 约束 / 入口 / 流转 / 状态 / 快照 / 层级 / 覆盖 / 偏差 / 裁决 / 触发 / 交付。

## 触发与自检

- 触发词见 frontmatter；每次触发 = 全量重生成（覆盖式）。
- 生成后自检（一次性命令，不立常驻脚本）：`wc -l` ≤ 250；五段标题 grep 齐；三件套 grep 齐；mermaid 块计数 ≥2 且 ≤12；单图节点自数 ≤30；**逐图渲染验证**——各图嵌入临时 HTML（mermaid CDN）浏览器验证渲染成功后删临时文件。
- 失忆测试由人执行（非 skill 内置）：隔 ≥3 天只读视图，≤15 分钟答三问（当前主线 / 关键决策所在文件 / 下一步），全达 = 通过。
