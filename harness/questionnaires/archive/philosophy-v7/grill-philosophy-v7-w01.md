7. 方法论治理需要主张 → 不变量 → 验证卡及失败恢复边界

## Q1. 「信息断层 → 返工」应承担多强的证据义务？(D1+D6)   [落盘: 处理报告;若形成长期验证要求,进入 TODO 或 OPEN-DECISIONS]

> **出题依据:**哲学 §1.2 将「数倍」「一小时 / 三天」标为作者经验性示例;§1.3 又把返工率与返工工时占比限定为反思提示,不设基线、观察窗口或阈值。这诚实降低了过度承诺,但也留下核心靶子几乎不可证伪的风险。

- [ ]  A. 删除或进一步收窄「规划通常较小、返工是时间黑洞」等比较句,只保留「信息断层会制造一类返工风险」的机制主张——证据负担最低,但哲学的动机力度会变弱
- [ ]  B. 保持当前经验启发式与代理指标提示,再补一句「不能据此判断方法有效」——维护成本低,但仍主要依赖采用者自评
- [ ]  🤔 我定不了 → 推迟/降风险
- [X]  C. 保留核心论断,但为它建立最小验证卡:适用范围、返工的操作性定义、基线/观察窗口、可能反例和重访条件;具体数据仍由采用项目收集——★推荐,因为把“为什么相信”与“如何验证”分开,不把学科借用冒充实证

## Q2. 「AI 替代 PM / QA / Reviewer / DevOps」会不会被读成「AI 替代判断权」？(D1+D4+D8)   [落盘: 处理报告;必要时列为哲学修订建议]

> **出题依据:**哲学 §2.1 明确「判断性决策永远由人做」,但 §2.2 的角色表使用「AI 替代传统角色」并把 QA、Code Reviewer、DevOps 等角色放在同一叙事中。当前表格有图例和人审说明,仍可能让读者把“角色替代”“执行替代”“责任替代”混为一谈。

- [ ]  A. 保持现状,依靠 §2.1 分工表图例和「人做最终确认」自行消歧——不增加正文,但把误读成本留给读者
- [ ]  B. 把角色替代说明全部移到实操文件,哲学只保留「AI 消除等待」——边界更干净,但哲学失去人与人断层的具体论证
- [ ]  🤔 我定不了 → 推迟/降风险
- [X]  C. 在哲学中明确每个角色只替代结构化执行与等待链,不替代目标、风险、验收或签字权,并将角色表的权限边界链接到 CONTEXT / delegate——★推荐,因为直接封堵“角色名被替换 = 判断权被替换”的跳步

## Q3. 80/20 判断成本原则应是修辞、路由规则,还是可测量目标？(D1+D5+D6)   [落盘: 处理报告;必要时进入方法不变量候选]

> **出题依据:**哲学 §3.1 已声明 80/20 是类 Pareto 的经验启发式、非定理且无量化模型;但 §3.1–§3.2 和方法论 §5.2 又用它决定何时走批量问卷、何时转单点深钻。若没有最低路由判据,同一问题可以被任意归类。

- [ ]  A. 保留 80/20 数字,但只作为帮助读者理解的修辞,不承担流程路由或验收义务——最轻量,但容易变成无约束口号
- [ ]  B. 删除数字,改成「可预知问题批量处理、依赖链深的问题单点深钻」的定性原则——减少伪精确,但失去原设计的判断成本记忆点
- [ ]  🤔 我定不了 → 推迟/降风险
- [X]  C. 保留数字作为经验量级,另加最小路由表:依赖链深度、是否需要即时反馈、可逆性/风险、能否离线作答四项决定分流,不把 80/20 当时间配额——★推荐,因为让原则可执行又不伪装成统计定律

## Q4. 双轨对照在哲学中应保留到什么强度？(D3+D4+D6+D7)   [落盘: 处理报告;若改变 pilot 边界,进入 OPEN-DECISIONS]

- [ ]  A. 将双轨升级为方法论默认闸门,所有关键决策都必须先跑 AI 全权影子——对照更完整,但与个人开发者成本边界和当前 pilot 状态冲突

- [ ]  🤔 我定不了 → 推迟/降风险
- [X]  C. 保留为有边界的运筹学启发式:哲学只规定影子/基线/人类仲裁/升级不可由 AI 自评,具体试跑协议与结果留在 OD/实操——★推荐,因为与现有实证和“规格不等于效果证据”的边界一致

## Q5. L1–L3 应继续称为「AI 黑盒三层次合一」吗？(D4+D5+D8)   [落盘: 处理报告;术语冲突若确认,进入 CONTEXT 修订建议]

> **出题依据:**哲学 §4.1 与 CONTEXT「AI 黑盒」都把 L1 决策过程、L2 依据追溯、L3 独立验证称为“三层次合一”;但 §4.4 已承认 L1 没有真正打开的对策、L3 有形式化 V&V 缺口。三者的证据类型和失败后果并不相同。

- [ ]  A. 保持「合一」并把三层当作一个不可拆的总风险——叙事集中,但可能暗示只要有一种留痕就同时治理三层
- [ ]  B. 把 L1、L2、L3 改成三个独立风险类别,分别建立强制证据和恢复协议——概念最精确,但可能把哲学推成完整 assurance 规格
- [ ]  🤔 我定不了 → 推迟/降风险
- [X]  C. 保留「AI 黑盒」总称,将「三层次合一」改成「三个相互独立、可叠加的不透明维度」,明确任何一层的证据不能替代另外两层——★推荐,因为保留统一立论同时阻止证据越权

## Q9. 「按项目 / 场景 / 工具调整」的自由度应由什么不可变底线约束？(D2+D3+D4+D5)   [落盘: 处理报告;若形成核心不变量,进入 ADR-0016 后续验证卡]

> **出题依据:**哲学 §五允许按项目、场景、工具调整,但 §2.1、§4.4、§4.5 又分别规定判断性决策归人、关键/单向门强制留痕、WAI 定底线。当前没有一处明确列出“可裁剪但不可取消”的最小核心,容易让裁剪变成静默绕过。

- [ ]  A. 所有原则都可按项目成本裁剪,只要用户主观认为风险可接受——最灵活,但失去方法论的最低安全边界
- [ ]  B. 五章全部按同一合规标准执行,不允许个人项目裁剪——边界清楚,但与个人开发者的成本目标和元原则冲突
- [ ]  🤔 我定不了 → 推迟/降风险
- [X]  C. 明确不可裁剪核心:人保留判断性决策与最终确认、单向门先停并留痕、L3 需要独立的人审/试玩/客观 oracle、冲突不得静默覆盖;其余流程按风险裁剪并记录理由与重访条件——★推荐,因为把“弹性”从无限豁免变成受约束的配置

## Q10. 「方法论文件自包含」与「哲学承载为什么」的边界应如何解释？(D6+D7+D8)   [落盘: 处理报告;必要时进入 ADR-0018 交叉审查清单]

> **出题依据:**方法论 v4 顶部称自己是“怎么做”的完整、自包含阐述,但同时把完整失败模式和安全科学解释链接到哲学;哲学顶部又把方法论文件定义为“怎么做”。双文件治理若不定义“自包含”的操作含义,读者会在“只读方法论是否足够执行”和“是否必须先读哲学”之间摇摆。

- [ ]  A. 保持「自包含」的字面强含义,接受方法论与哲学之间存在重复或跨读要求——导航简单,但与现有交叉引用不完全一致
- [ ]  B. 删除方法论的「自包含」承诺,明确它必须与哲学一起阅读——边界诚实,但削弱方法论作为独立操作文件的可用性
- [ ]  🤔 我定不了 → 推迟/降风险
- [X]  C. 将“自包含”限定为可独立执行流程与操作规范;哲学负责动机、失败模式和责任边界,允许方法论链接哲学但不把关键执行步骤藏在哲学里,并把该判据加入双文件交叉审查——★推荐,因为同时保留独立可用性和 canonical 双文件的分工
