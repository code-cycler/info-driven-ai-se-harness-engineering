# ADR-0016: 核心方法主张的验证与变更合同

- 状态:accepted(2026-08-13,grill-Q philosophy-v5 W04 Q2–Q5/Q8)
- 决策日期:2026-08-13

## 背景

本项目已经有「AI 不替人做判断性决策、关键决策留痕、独立验证、发现文档与现实冲突先停」等核心原则,但它们主要分散在哲学、方法论、实操文件和各 skill 规格中。相较之下,同级对标仓库即使尚无可运行实现,仍把不变量、验收属性、实现映射和暂定状态分开写,避免把「规格存在」误读成「实现或效果已经验证」。

grill-Q W04 进一步确认:本项目需要吸收这种结构化优点,但不把哲学直接改造成完整系统架构规格。Q1 关于是否完整采用 Level 1/2/3 的选择与 Q10 的最小切片选择存在冲突,单独留在 [OD-20](../../docs/OPEN-DECISIONS.md),本 ADR 只记录两者的共同治理底座。

## 决策

1. **方法不变量**:抽取 6–10 条核心方法不变量。每条至少记录:稳定 ID、主张、适用范围、违反症状、最小证据、例外边界和唯一权威文件。详细操作仍归 skill / 实操层。
2. **最小验证卡**:每条核心主张建立验证卡,至少包含:主张、适用范围、反例、代理指标、独立证据、阈值或重访条件。哲学保留原则,卡片与实测记录落在实操或 `harness/` 区。首批四张卡(`MC-01` 信息断层、`MC-02` 判断权、`MC-03` L3 assurance、`MC-04` canonical 交叉挑战)及其覆盖矩阵见 [方法论治理最小切片](../design/methodology-governance/LLD.md),当前仍标为目标治理能力 / 未验证。
3. **失败处理骨架**:发现矛盾或审查缺口后,按「标记影响范围 → 暂停不可逆动作 → 保留事实与副作用 → 选择性恢复或回滚 → 复盘并更新规范」处理。各 skill 定义具体状态和动作。
   - **实施补充(2026-08-14,W02 Q3)**:方法级最小状态协议使用「疑似失效 → 暂停采用 → 已知缺口 / 临时占位 → 恢复验证」这组状态语义;状态变化必须能指向处理报告、验证卡、ADR / OD 或其他最小证据入口。具体动作仍由对应 skill 定义,不在哲学中建立统一状态机或恢复 API。
4. **核心主张变更清单**:修改 canonical 主张或不可逆治理边界前,列出唯一权威、受影响引用/skill、是否改变不变量、所需验证、当前/已提交/已发布状态。普通局部措辞修订不强制套用完整清单。
5. **证据边界**:本仓库的脚本、文档检查和 skill dogfood 只能证明相应过程在本仓库中的执行状态;不能单独证明下游项目的开发效率、质量或因果效果。下游效果由采用项目的 dogfood / retro 验证。

## 替代方案(被否决)

- **给所有流程规则逐条编号**:可追踪性更强,但会把方法论膨胀成规格书,不符合个人开发者的成本边界。
- **要求外部学术或统计研究后才保留核心主张**:独立性更强,但成本与当前方法论定位不匹配,会冻结迭代。
- **在哲学中加入完整流程状态机**:实现细节过多;保留方法级骨架,具体状态交给 skill / 实操层。

## 后果

- (+) 把核心原则从散文主张连接到最小证据、失败处理和变更影响,降低跨文件漂移与「规格即证据」误读。
- (+) 保留哲学/方法论/实操三块现有结构,不因对标仓库而立即进行大规模迁移。
- (−) 新增不变量、验证卡和变更清单会产生维护成本,也可能诱发新的形式主义;需用数量上限和核心主张范围控制。
- (−) 完整 Level 1/2/3 是否适合本项目仍未决,见 [OD-20](../../docs/OPEN-DECISIONS.md)。
