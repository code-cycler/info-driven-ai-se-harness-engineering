## 目标与受众

- **一句话目标**:为治理历史建立「移层不删除」机制——三域治理历史单独保存(载体统一命名 CHANGELOG,望名知意)+ 索引导向,换 LLM 上下文纯净与人的可检索性;信息零丢失(只移不删)。
- **受众双重定义**:① AI 会话(常驻上下文消费者:SKILL.md 每次触发加载、CLAUDE.md 每次会话自动加载——受益 = 上下文密度提升,历史不占常驻位);② 人(治理历史检索者——受益 = 单一去处 + 索引可达,「这条规则为什么是这样」一跳可答)。两受众的验收分别定义,不以单一「变短」为目标。

## 动机

- **锚定第一支柱(有效上下文)**:本仓库是方法论生产车间,自身形态应示范「有效上下文」主张——SKILL.md 是每次触发的常驻 token 成本(8 skill 合计约千行)、CLAUDE.md 是每次会话的自动加载成本(109 行中「仓库状态」节占 25 行);治理历史占位 = 第一支柱在自家仓库的违例。
- **OD-10(分发洁净)机制化推进**:本 feature 与 ADR-0023 同持「移层而非删除」逻辑;完成 + 首轮增量验证后,OD-10 重访条件更充分(全局侧提前达成分发洁净目标态,见下)。

## 范围(做什么;明确不做什么)

**做**:
- **三域治理历史分离**:① skills/ 区(8 skill 的 SKILL.md 注记 + DESIGN.md 过程性历史);② harness/design/ 区(层文件内嵌治理历史);③ 项目 CLAUDE.md「仓库状态」节。
- **双侧形态分工机制**(W00 补充声明②裁决):`~/.claude/skills/`(全局)= **分发洁净形态**——模拟开发者开箱即用,不记录演进;本仓库 `skills/`(项目)= **车间完整形态**——保留完整演进历史。双侧从「逐字节一致(仅脱敏差)」转为**常态性形态分工**。
- **doctor-harness 升级以承载本机制**(W00 补充声明①裁决,Q4-B):HARNESS-RULES 增「治理历史布局」节 + skills-sync-check 语义升级(Q3-C 历史层反向豁免)+ MIGRATION-FLOW 沿用 + doctor-harness SKILL.md 职责补条(治理历史载体的维护/迁移触发/增量记录规则)。
- **存量迁移执行 = 一次 long-running 收口**(Q5-B):单次会话分阶段——P0 协议落盘(HARNESS-RULES 节 + sync-check 升级)→ P1 skill 域(8 skill × 注记迁移 + CHANGELOG 建立)→ P2 harness/design/ 域 → P3 CLAUDE.md 域 → P4 全局侧重整(剥历史层成分发形态)+ 复跑三脚本验收。不新造迁移机制(走既有 doctor-harness/MIGRATION-FLOW + 铁律 8)。

**不做(排除项显式)**:
- TODO.md 历史块(定模裁决排除);
- grill-with-docs 分工/命名重估(TODO 独立线,已转单点深钻,触 OD-22);
- OD-8 引擎副本漂移治理(既有独立治理线,本 feature 不动四副本引擎本身);
- 归档问卷(已单独保存);harness/adr/(ADR 本身就是决策历史标准载体,不动);
- 发布管道(项目 → 全局的分发形态生成产物,Q3-B 被否项)——留 OD-10 终态候选,不与本次绑定。

## 核心场景

1. **AI 会话加载**:skill 触发 → SKILL.md 只载规则本体(治理历史经一行索引导向,按需才读);CLAUDE.md 载当前状态快照而非逐年历史——上下文密度提升,历史不占常驻位。
2. **人回溯决策**:「这条规则为什么是这样/当年怎么裁的」→ 从规则所在文件经索引行一跳到 CHANGELOG 条目(条目带反向指针「影响:<文件>#<节>」)——可追溯性不降(硬约束,非排序项)。
3. **增量维护**:新裁决/修订/dogfood 发生时,历史入 CHANGELOG、规则入规则文件、重复教训(≥2 次)按 ADR-0023 升格机制回常驻层——增量事件有固定去处,机制不因存量迁完而失效。

## 目标状态画像(三域终态)

- **skills/ 域**:
  - SKILL.md **两侧同形**(Q1-C):只留规则现值 + 文件级一行索引导向;**出处型与叙述型注记全部迁出**(推翻 2026-08-19「全量迁移缓行」评估,ADR-0023 决策 1 原原则回归)——「上限 10 题(2026-08-08 裁决收紧,原 10–15)」类注记整体迁 CHANGELOG 条目,SKILL.md 只留「每波上限 10 题」。
  - 每个 skill 目录内一份 `CHANGELOG.md`(追加式,doctor-harness 现役先例推广;粒度与条目格式 = L1 契约),**仅项目侧存在**。
  - DESIGN.md(仅项目侧)收敛为「设计决策」(W00-10);过程性历史(引擎同步记录/dogfood 轮次叙述/裁决史)迁 CHANGELOG。
  - **有意分叉声明抽成独立小文件 `FORK-NOTES.md`**(小波澄清裁决):仅含分叉条目(通常 <10 行),**双侧都有且逐字节一致**(sync-check 常规共有文件,零新语义);DESIGN.md 其余内容不进全局。
  - 全局侧文件集 = SKILL.md + 引擎/模板文件 + FORK-NOTES.md(Q2-A);无 DESIGN.md、无 CHANGELOG。
- **harness/design/ 域**(W00-11):层文件(L0/L1)内嵌治理历史迁至该 feature 的历史载体(载体落位与命名 = L1 契约);层文件本体只留当前有效设计 + 索引行;与已有 `history/` 版本子目录机制的关系由 L1 裁定。
- **CLAUDE.md 域**(W00-12,**落点修正 2026-08-20 L1 W00-10**):「仓库状态」节瘦身为当前状态快照(**≤5 行**)+ 双指针;历史条目迁 **`harness/STATUS-LOG.md`(新载体)**——修正原因:L1 核实根 CHANGELOG.md 记录规则原文「凡采用者可感知的变更必记,纯仓库内部治理不记」,与内部状态史不兼容,W00-12「职责重叠」前提有误;根 CHANGELOG 保持纯对外语义。
- **索引指针强制配套**(W00-13):凡历史迁出处,原位置必留一行指针——防「历史消失了但没人知道去哪找」。

## 验收标准(可独立验证条目式)

1. **注记迁净**:8 个 SKILL.md 中纯日期型治理注记 grep = 0(「规则出处不可分割」型不再豁免——本 feature 裁决全迁;迁移对照表显式落盘备查)。
2. **信息不丢**:每条迁出内容在目标载体逐字可查,迁移报告对照(移而非删;waste/ 不用,直接迁 CHANGELOG)。
3. **三脚本全绿**:断链 0 + harness-check 0 违规 + skills-sync-check 0 违规(升级后语义)。
4. **CLAUDE.md 状态节 ≤ 5 行**(快照 + 指针)。
5. **增量协议在位(迁移自身事件即首验,压测 Q5-C)**:P0–P4 执行本身产生的真实治理事件(ADR-0024 落盘、压测回灌裁决、铁律 8 改写、HARNESS-RULES 第九节增补)按新协议写入 CHANGELOG = 即时活体验证,不等未来事件;P4 收口 DoD = 验收 1–4+6 + 本 feature 自身事件入 CHANGELOG 抽查。
6. **检索 ≤ 2 跳**:「查一条规则的裁决出处」路径 = 规则 → 索引行 → CHANGELOG 条目;抽样 3 条历史规则实测走通。

## 风险与约束

- **风险四项**(W00-16,② 机制更新为 Q3-C):① 规则出处误伤(迁移时丢上下文)→ 防护 = 迁移对照表 + 迁移后人工抽检;② 双侧同步成本 → 防护 = **历史层类规则**(`*/CHANGELOG.md` 仅项目侧存在 = 合法,存在性反向豁免;doctor-harness/CHANGELOG.md 现白名单例转入类规则),FORK-NOTES.md 双侧一致为常规共有文件;③ 检索链变长 → ADR-0023 已认此代价,索引行 + 验收 6(≤2 跳)对冲;④ 升格机制断链 → L1 契约显式衔接 ADR-0023 协议(重复教训 ≥2 次回常驻层)。
- **权威关系**(W00-17):本设计产出的布局协议**落 HARNESS-RULES.md**(harness/ 域)+ 仓库既有权威文件(skill 域),**不另立第二权威源**;规则修订走 HARNESS-RULES 自身的 CHANGELOG 留痕。
- **可追溯性不降 + 信息零丢失 = 硬约束**(W00-19),违任一 = 方案否决;价值排序:LLM 上下文纯净 > 人检索体验 > 迁移维护成本。
