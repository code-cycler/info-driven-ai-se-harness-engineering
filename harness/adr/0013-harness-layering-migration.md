# ADR-0013: harness 分层迁移——本仓库设计/归档重组执行决策

- 状态:proposed→accepted(2026-08-08,design-Q hld W00 #14 裁定:立 ADR)
- 日期:2026-08-08
- **F019 执行实证(2026-08-08,grill-Q Q3 回灌)**:必做档执行发现 design/ **已天然分层**(methodology 系列裸放 + feature 系列已建目录),**无需物理重组**;本次迁移实为「判定句核对确认 + 9 处归档链接层级修复(../→../../)」。本 ADR 标题/必做档措辞「重组/聚合」为能力声明(不合规时如何做),非本次必然动作;实际 dogfood 产出 = 确认现状合规 + 修链接。

## 背景

ADR-0012 定义了 harness 内部分层规则(design/<feature>/ 判定句 + 归属判据 + 归档子目录)。本仓库 `harness/` 现状是设计/子目录与裸放混用、归档平铺,需按新规则重组。迁移会破坏既有相对链接——问卷尾部处理报告摘要、SKILL.md 引用、跨目录链接(先例:2026-08-05 harness 迁移曾 96 断链 → 7 豁免)。

## 决策

1. **迁移范围分两档**:
   - **必做档**:`design/` 按 feature 聚合(现状混用最该治)——methodology 系列裸放文件(VISION.md/hld_v2/lld_v2/hld-methodology-separation)按 ADR-0012 判定句归类:全局设计裸放保留,feature 系列已建目录保留;逐条核对归属。
   - **可选档**(TBD):`questionnaires/` 新归档入子目录(存量不挪)+ `adr/` 维持编号平铺(ADR 编号连续是硬约束,不因 feature 分组破坏)。
2. **迁移方式**:一次性完整迁移(挪文件 + 重算相对链接 + 规格同步 + 断链回归),**不渐进半途**;自动化迁移脚本不写(一次性工作),手动 + MIGRATION-FLOW 文档步骤 + 校验脚本验证。
3. **迁移 DoD**:design/ 按 feature 聚合完成、相对链接全部重算、断链回归 0 新增、各 SKILL.md 引用同步、校验脚本(harness-check.py)跑 0 违规。
4. **迁移作为独立行动项**进 TODO,带 DoD,不随 doctor-for-harness 设计自动执行。

## 替代方案(被否决项)

- **只分 design/ 不碰其它(最小迁移面)**:可选档全不做,迁移面最小。部分采纳——必做档 = design/(本决策 1),可选档标 TBD 不否决。
- **三件全分(design/ + questionnaires/ + adr/ 全重组)**:迁移面最大,破坏 ADR 编号平铺(硬约束)。否决——ADR 编号连续优先,不因 feature 分组破坏。
- **渐进半途迁移**:分批挪文件。否决——中途退出留下半迁移状态,链接/规格不一致(压测 Q6 裁决+先例)。

## 后果

- (+) 分层落地后,design/ 组织与 ADR-0012 规则一致,新会话 agent 可循规则;
- (+) 迁移作为独立行动项带 DoD,可验证、可回退(git)。
- (−) 迁移期相对链接临时失效,需一次性断链回归(先例:96 断链 → 7 豁免);
- (−) 可选档(questionnaires/adr)未动,归档仍平铺,检索成本随新 feature 子目录化逐步缓解(自然演进)。
