# delegate · 决策类下放

> 把「简单决策下放给 AI,人专注判断权」做成可治理、可留痕、可收回的机制。
> 来源:宿主项目「决策下放」OD 条目(grill-questionnaire 压测产出,时间线见 CHANGELOG)。当前为 dogfood 试点版,反馈回该 OD 条目。

## 铁律(不可违反)

1. **判断权永不下放** — 产品、工程、安全、合并四类判断权永远在人;本 skill 只处理执行层「决策类」。
2. **AI 无自分类权** — 决策点不在白名单内 → 一律问人;AI 只能「建议升级」(提议把某类加入白名单,人决定)。
3. **禁区优先** — 某决策同时看似落在白名单与永不下放清单时,按禁区处理。
4. **每例留痕,不批处理** — 每例自主决策立即写 delegation-log.md;原始信息不丢失,只增不改。
5. **清单变更只能人发起** — AI 可提议,人批准;变更必须记 delegation.md 的 Changelog。
6. **收回优先** — 单条目收回条件命中即停(该决策类 → suspended),不辩解、不延续;整体开关 `enabled: false` 时全部问人。

## 文件约定

| 文件 | 作用 | 性质 |
|---|---|---|
| `<项目根>/delegation.md` | 治理文件:白名单、禁区、收回条件、整体开关、Changelog | 唯一事实源;变更须人发起 |
| `<项目根>/delegation-log.md` | 可审计队列:每例 AI 自主决策一条 | 追加式日志;只增不改 |

两文件都纳入版本控制。模板见 [templates/](./templates/)。

## 主流程

### 1. init(项目/工程一开始,或首次启用)

1. 读项目规范(CLAUDE.md / AGENTS.md / 既有约定),按 `templates/delegation-template.md` 起草本项目 delegation.md:白名单候选逐类列出,每类写清范围/约束与收回触发条件。
2. **人逐类审查**:删、改、确认;禁区清单逐条过。
3. 定稿后记 Changelog 首条(初始枚举,发起 = 人),**同步创建空 delegation-log.md(含表头)**——log 文件必须在 init 时就存在,不得事后补建。
4. 白名单未定稿前,一切按「全部问人」运行。

### 2. 日常执行(遇到决策点时)

1. 判断该决策点属于哪个决策类:
   - **在白名单内且状态 active** → 自主执行,立即写 delegation-log.md(决策类、决定、依据、可逆性)。
   - **触及禁区** → 绝不自主,按项目既有流程交人。
   - **都不在** → 正常问人;若该类反复出现,可「建议升级」:向人提议新增决策类(附:类名、范围、收回条件、已出现次数),人批准后走清单变更。
2. 会话中涉及决策前先确认 delegation.md 存在且 `enabled: true`;文件缺失或开关关闭 = 全部问人。

### 3. 收回

- **单条目**:某决策类的收回触发条件命中(如「命名引发歧义 1 次”) → 该类状态改 `suspended`、记 Changelog、写日志、明确告知人;恢复须人显式操作。
- **整体**:人将 `enabled` 置 `false`(或口头宣布收回)→ 立即全部问人,记 Changelog。

### 4. 回顾(任务结束 / retro)

- **log 存在性检查(强制)**:先确认 delegation-log.md 存在。文件缺失 = 流程缺口(留痕漏执行),必须在回顾报告中显式标记并补建(可恢复部分事后补录,标注「事后恢复」);不得静默继续。
- 汇总本期 delegation-log.md:总条数、各决策类分布、升级问人次数、误判/收回事件。**零条目**须显式说明「本期无 AI 自主决策」(零条目本身是必须解释的事实,不是默认成功)。
- 人回顾后决定:维持、调整清单(走变更)、或收回。
- dogfood 试点项目:把汇总数据(升级问人率、事后否决/回退率、误判事件数、主观疲劳前后对比)带回宿主项目「决策下放」OD 条目。

## 清单变更治理

- 新增/调整/删除决策类 = delegation.md 的显式修订:人发起,记 Changelog(日期、变更、发起、原因)。
- AI 提议只进「建议升级」,不直接改文件。
- 渐进侵蚀防线:任何「这个也很简单嘛」都必须走同一条变更流程,无例外。

## 全权模式(mode: full)

grill-Q 压测产出(OD-13):供「AI 全权自治」双轨对照(影子 / 冠军挑战者)使用的宽松模式。

- **开关**:delegation.md frontmatter `mode: full`(`strict` 为默认);切换只能人发起,记 Changelog。
- **语义**:`mode: full` 开启时,白名单语义反转为**排除集**——「未列入禁区(永不下放清单)即默认可执行」;`strict` 下保持原白名单语义。
- **底线不变**:禁区清单、**发布 / 付费 / 对外传播 / 删除数据四类永不自动执行**、判断权(产品/工程/安全/合并)永不下放——三者在 `full` 下同样有效。
- **留痕不变**:每条自主决策仍写 delegation-log.md(只增不改)。
- **实测条款(新纪律)**:「AI 先实测(只读:工具 / 脚本 / bash 命令)可自主执行;实测后的决策归类仍交人,或归入 `full` 模式排除集」——解决「AI 先实测再判定」与「AI 无自分类权」的张力。实测动作自主**只限只读**;写操作仍在白名单/排除集框架内。
- **收回优先**:`full` 下同样适用——收回条件命中即停,不辩解。

## 与家族 skill 的关系

- 与 design-questionnaire / grill-questionnaire 正交:它们管「人怎么做批量决策」,delegate 管「哪些执行层决策不再问人」。
- 问卷引擎的 🤔 逃生舱(降风险协议)是单次决策的临时让渡;delegate 是枚举决策类的常驻下放,两者不互相替代。
